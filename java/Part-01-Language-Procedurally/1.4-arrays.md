# 1.4 — Arrays

> **What this is:** Java's lowest-level container, and **the odd one out in the type
> system**. Everything strange about arrays is explained by the fact that they predate
> generics by eight years.

---

## Coming from JS/Python/Dart

A JS array is a resizable object with dozens of methods. A Python list grows.
**A Java array is a fixed-length block of memory with almost no methods.**

The thing you actually want most of the time is `ArrayList` (Part 05). Arrays are
worth knowing because they're underneath everything, and because their weirdness
explains *why generics were designed the way they were*.

---

## The concepts

### Declaration and creation

```java
int[] nums = new int[5];              // length 5, all zeros
int[] nums2 = {1, 2, 3};              // literal form
int[] nums3 = new int[]{1, 2, 3};     // needed when not in a declaration

String[] names = new String[3];       // all null

// The C-style form. Legal, but don't.
int nums4[] = new int[5];             // ⚠️ compiles, ugly, avoid
```

**Default element values** — arrays are always initialised:

| Element type | Default |
|---|---|
| numeric (`int`, `double`…) | `0` / `0.0` |
| `boolean` | `false` |
| `char` | `'\u0000'` |
| any reference type | `null` |

**Length is fixed at creation and never changes.**

```java
nums.length        // a FIELD, not a method — no parentheses
"hi".length()      // a METHOD on String — parentheses
list.size()        // a METHOD on collections
```

Three different spellings for the same idea. Java's age showing.

### Multi-dimensional arrays are arrays of arrays

```java
int[][] grid = new int[3][4];     // 3 rows, each an int[4]
grid[0][0] = 1;
```

There is no true 2D array in Java. `grid` is an array of 3 references, each pointing at
a separate `int[4]` somewhere else on the heap.

**Jagged arrays** — the rows don't have to be the same length:

```java
int[][] jagged = new int[3][];
jagged[0] = new int[2];
jagged[1] = new int[5];
jagged[2] = new int[1];
```

**What that costs:** a `int[1000][1000]` is 1,001 separate objects scattered across the
heap, not one contiguous block. Every `grid[i][j]` is **two** memory hops. For heavy
numeric work, people flatten to `int[1_000_000]` and index with `i * width + j`
to keep it cache-friendly. (Part 08 covers why this matters.)

### The `Arrays` utility class

Arrays have no useful methods, so everything lives in `java.util.Arrays`:

```java
import java.util.Arrays;

int[] a = {3, 1, 2};

Arrays.sort(a);                  // sorts in place → [1, 2, 3]
Arrays.binarySearch(a, 2);       // 1  ← only valid on a SORTED array
Arrays.fill(a, 0);               // [0, 0, 0]
int[] b = Arrays.copyOf(a, 5);   // [0,0,0,0,0] — grow/shrink
int[] c = Arrays.copyOfRange(a, 1, 3);
Arrays.toString(a);              // "[0, 0, 0]"
Arrays.stream(a);                // → IntStream (Part 06)
```

**`equals` vs `deepEquals`, `toString` vs `deepToString`:**

```java
int[][] x = {{1,2},{3,4}};
int[][] y = {{1,2},{3,4}};

Arrays.equals(x, y)       // false ← compares the inner ARRAY REFERENCES
Arrays.deepEquals(x, y)   // true  ← recurses into nested arrays

Arrays.toString(x)        // "[[I@1b6d3586, [I@4554617c]"  ← useless
Arrays.deepToString(x)    // "[[1, 2], [3, 4]]"            ← what you want
```

### Why arrays print as `[I@1b6d3586`

```java
int[] a = {1, 2, 3};
IO.println(a);          // [I@1b6d3586
```

This is your **first encounter with the default `toString()`**, and it's worth decoding
because you'll see this pattern constantly:

```
[I@1b6d3586
│││ └─ the identity hash code, in hex
││└─── @
│└──── I = int   (Z=boolean, B=byte, D=double, L<Class>; = an object)
└───── [ = "array of"
```

So: *an array of int, at identity hash 1b6d3586.* Arrays never overrode `toString()`,
so they inherit `Object`'s, which prints the class name and hash (see 2.5).

**Fix:** `Arrays.toString(a)` or `Arrays.deepToString(a)`.

### Array covariance — and why generics refused to repeat it

This is the important part of the page.

```java
Object[] objects = new String[1];   // ✅ compiles! A String[] IS-A Object[]
objects[0] = 42;                    // 💥 ArrayStoreException at RUNTIME
```

Arrays are **covariant**: `String[]` is treated as a subtype of `Object[]`. That looks
convenient, but it means the compiler cannot catch the error above. Java has to check
the type of every single array store **at runtime**, forever, in every program.

That was judged a mistake. So when generics arrived in Java 5:

```java
List<Object> list = new ArrayList<String>();   // ❌ compile error. Good.
```

Generics are **invariant** — `List<String>` is *not* a `List<Object>`. It feels more
restrictive, and it's the reason wildcards (`? extends`, `? super`) exist in Part 03.

> **Hold onto this.** "Arrays are covariant and pay for it at runtime; generics are
> invariant and pay for it in syntax" explains most of Part 03.

### When arrays still beat collections

Use an array when:
- You need **primitives without boxing** — `int[1_000_000]` is 4MB; `List<Integer>` is
  ~20MB and chases pointers.
- The size is **genuinely fixed and known**.
- You're writing the internals of a data structure (`ArrayList` is backed by an array).
- Working with an API that returns one.

Use `ArrayList` (Part 05) for everything else — which is most things.

> **Premature optimisation warning:** don't reach for arrays because they "feel faster".
> For a list of 50 users, `ArrayList` is correct and the difference is unmeasurable.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `array.length()` | It's a field: `array.length`, no parens |
| `IO.println(array)` | Prints `[I@...`. Use `Arrays.toString()` |
| `Arrays.equals` on 2D | Use `deepEquals` |
| `binarySearch` on unsorted | Returns garbage, no error |
| `Object[] o = new String[1]` | Compiles, then throws at runtime |
| Resizing an array | You can't. `Arrays.copyOf` makes a new one |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `int arr[]` C-style declaration | `int[] arr` |
| Arrays as your default collection | `ArrayList` / `List.of()` |

## Recap

| Concept | One line |
|---|---|
| Fixed length | Set at creation, never changes |
| `.length` | A field, not a method |
| 2D = array of arrays | Jagged allowed, costs an extra memory hop |
| `Arrays.*` | All the utility methods live here |
| `[I@1b6d3586` | Default `Object.toString()` — class + identity hash |
| **Covariance** | `String[]` IS-A `Object[]` → runtime `ArrayStoreException`. Generics refused this. |
