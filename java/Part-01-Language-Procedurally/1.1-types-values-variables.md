# 1.1 — Types, values, variables

> **What this is:** The one genuinely new idea coming from a dynamic language —
> a variable has a type that exists **before the program runs**.

---

## Coming from JS/Python/Dart

In Python, `x = 5` then `x = "hi"` is fine. The *value* has a type; the *variable*
doesn't. In Java the **variable** has a type, fixed at compile time, and the compiler
rejects the program if you break it.

Dart is your closest reference point — `int x = 5;` works the same way. PHP with
`declare(strict_types=1)` is halfway there.

```java
int x = 5;
x = "hi";   // ❌ compile error. The program never runs.
```

That's the whole idea. The rest of this page is the *details* Java is explicit about.

---

## The concepts

### Static typing — what the compiler checks and what it cannot

The compiler checks: does this type have this method? Is this assignment legal?
Is this method call's argument the right type?

It does **not** check: is this list empty? is this value `null`? is this index in range?
Those are runtime problems. Knowing the boundary tells you which bugs are possible at all
(more in 1.7).

### The eight primitives

These are not objects. They hold a raw value directly.

| Type | Size | Range / notes | Default |
|---|---|---|---|
| `byte` | 8 bit | −128 … 127 | `0` |
| `short` | 16 bit | −32,768 … 32,767 | `0` |
| `int` | 32 bit | ±2.1 billion — **your default whole number** | `0` |
| `long` | 64 bit | ±9.2 quintillion | `0L` |
| `float` | 32 bit | decimal, imprecise | `0.0f` |
| `double` | 64 bit | decimal, imprecise — **your default decimal** | `0.0d` |
| `char` | 16 bit | a UTF-16 code unit | `'\u0000'` |
| `boolean` | — | `true` / `false` | `false` |

> **Default** = the value a *field* gets if you don't assign one. Local variables get
> no default — the compiler forces you to assign before use.

### Reference types vs primitives — the distinction that explains most Java behaviour

```java
int a = 5;              // the variable HOLDS 5
String s = "hello";     // the variable HOLDS AN ARROW to a String somewhere in memory
```

- A **primitive** variable contains the value.
- A **reference** variable contains an address pointing at an object on the heap.

Everything that is not one of the eight primitives is a reference type. This single
distinction explains `==` vs `.equals()`, `null`, pass-by-value (1.5), and most of
Part 08.

### Integer overflow is silent

```java
int big = Integer.MAX_VALUE;   // 2147483647
IO.println(big + 1);           // -2147483648   ← wraps around, no error
```

Java does not throw. It wraps. If you need it to fail loudly:

```java
Math.addExact(big, 1);   // throws ArithmeticException
// also: subtractExact, multiplyExact, incrementExact
```

### Floating point: `0.1 + 0.2 != 0.3`

```java
IO.println(0.1 + 0.2);            // 0.30000000000000004
IO.println(0.1 + 0.2 == 0.3);     // false
```

Same as JS, same as Python — it's IEEE 754, not a Java quirk.

> **`double` is wrong for money.** Always. Use `BigDecimal` (Part 11.2) or store
> integer cents in a `long`.

```java
// ❌ 0.30000000000000004 worth of bug
double total = 0.1 + 0.2;

// ✅
BigDecimal total = new BigDecimal("0.1").add(new BigDecimal("0.2"));  // 0.3
```

### `char` is not a character

`char` is a **UTF-16 code unit**, 16 bits. Anything outside the Basic Multilingual Plane —
emoji, many CJK extensions — needs **two** chars (a surrogate pair).

```java
String emoji = "😀";
IO.println(emoji.length());            // 2   ← not 1
IO.println(emoji.codePointCount(0, 2)); // 1   ← the real answer
```

Vocabulary: **code point** = the actual character. **Code unit** = a 16-bit chunk.
A `char` is a code unit. JS has exactly this problem too — `"😀".length === 2`.

### Literals

```java
int million  = 1_000_000;    // underscores for readability
int hex      = 0xFF;         // 255
int binary   = 0b1010;       // 10
long big     = 5_000_000_000L;  // L required — without it, int overflow
float f      = 1.5f;         // f required — a decimal literal is double by default
double d     = 1.5d;         // d optional
```

### Casting

```java
// Widening — automatic, always safe
int i = 100;
long l = i;
double d = l;

// Narrowing — explicit, can silently truncate
double pi = 3.99;
int truncated = (int) pi;    // 3   ← truncates, does NOT round

int big = 300;
byte b = (byte) big;         // 44  ← silently wrong
```

> The compiler forces the cast so you have to *acknowledge* the risk. It does not
> prevent it.

### Wrapper types and autoboxing

Every primitive has an object version: `int`→`Integer`, `double`→`Double`, etc.
You need them because collections can only hold objects (`List<int>` is illegal;
`List<Integer>` is fine).

```java
Integer boxed = 5;      // autoboxing:   int → Integer
int unboxed = boxed;    // unboxing:     Integer → int
```

**Trap 1 — the null surprise:**
```java
Integer maybe = null;
int x = maybe;          // 💥 NullPointerException at runtime
```
A `Integer` can be `null`. An `int` cannot. Unboxing `null` explodes.

**Trap 2 — the integer cache:**
```java
Integer a = 127, b = 127;
IO.println(a == b);     // true   ← cached

Integer c = 128, d = 128;
IO.println(c == d);     // false  ← different objects!

IO.println(c.equals(d)); // true  ← the correct comparison
```
Java caches `Integer` objects from −128 to 127. Outside that range you get new objects,
and `==` compares *references*. **Never use `==` on wrappers.**

### `var` — local type inference `Java 10`

```java
var name = "Basha";                  // String
var count = 10;                      // int
var list = new ArrayList<String>();  // ArrayList<String>
```

What it **cannot** do:
```java
var x;              // ❌ no initialiser
var y = null;       // ❌ nothing to infer
// ❌ not allowed on fields, method parameters, or return types
```

> `var` is **not** JavaScript's `var`. The type is still fixed and still checked — you
> just didn't type it out. It's Dart's `var`, or C#'s.

Use it when the right-hand side already says the type
(`var user = new User()`), skip it when it doesn't (`var x = getThing()` — now the
reader has no idea).

### `final` on locals

```java
final int x = 5;
x = 6;              // ❌ compile error
```

**Effectively final** — a variable that is never reassigned, even without the keyword.
The compiler tracks this, and it matters in Part 06 (lambdas can only capture
effectively-final variables) and 2.9.

```java
int y = 5;          // never reassigned → effectively final
Runnable r = () -> IO.println(y);   // ✅ allowed

int z = 5;
z = 6;              // reassigned → NOT effectively final
Runnable r2 = () -> IO.println(z);  // ❌ compile error
```

### `null`

`null` is a value that any reference variable can hold. It is **not a type**, and it
is not an object.

```java
String s = null;
s.length();          // 💥 NullPointerException
```

`Java 14` gave you **helpful NPE messages**, which are genuinely excellent:
```
Cannot invoke "String.length()" because "<local1>" is null
```

Alternatives you'll meet later: `Optional` (6.7), `Objects.requireNonNull` (2.10),
and designing so `null` never gets in.

## ⚠️ Traps

| Trap | Fix |
|---|---|
| `==` on `Integer` | Use `.equals()` — always |
| Unboxing a `null` wrapper | Check for null, or don't use wrappers for arithmetic |
| `double` for money | `BigDecimal` |
| `(int) 3.99` expecting 4 | It truncates to 3. Use `Math.round()` |
| `"😀".length() == 1` | It's 2. `char` is a code unit |
| Integer overflow | Use `Math.addExact` if it must not wrap |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `new Integer(5)` | `Integer.valueOf(5)` or just `5` — the constructor is deprecated for removal |
| Raw `double` for currency | `BigDecimal` |

---

## Recap

| Concept | One line |
|---|---|
| Static typing | The variable has a type, checked before the program runs |
| 8 primitives | Hold the value directly |
| Reference types | Hold an arrow to a heap object |
| Autoboxing | `int` ↔ `Integer`, with a `null` trap and a `==` trap |
| `var` | Infer the type, still fully typed |
| `final` / effectively final | Never reassigned — matters for lambdas |
