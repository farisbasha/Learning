# 1.2 — Operators and control flow

> **What this is:** Mostly familiar. Two things are not: **integer division**, and
> **what `switch` became**.

---

## Coming from JS/Python/Dart

Nearly all of this is identical to what you know. Three differences:

| | JS/Python | Java |
|---|---|---|
| `7 / 2` | `3.5` | **`3`** — integer division |
| `if (x)` where x is a number | truthy/falsy | ❌ compile error — must be `boolean` |
| `switch` | statement only | statement **and expression** |

That last one is the big one.

---

## The concepts

### Integer division — the daily gotcha

```java
IO.println(7 / 2);       // 3     ← both operands are int → int result
IO.println(7 / 2.0);     // 3.5   ← one is double → double result
IO.println(7 % 2);       // 1
```

If both sides are integers, the result is an integer and the remainder is **discarded**.

**Modulo with negatives** — Java keeps the sign of the *dividend*:

```java
IO.println( 7 % 3);      //  1
IO.println(-7 % 3);      // -1    ← Python would give 2 here!
IO.println( 7 % -3);     //  1
```

This differs from Python. If you want a always-positive result:
```java
Math.floorMod(-7, 3);    // 2
```

### Compound assignment hides a cast

```java
byte b = 10;
b = b + 5;    // ❌ compile error — b + 5 is an int
b += 5;       // ✅ compiles — because += silently inserts (byte)
```

`+=` is not just shorthand. It includes an implicit narrowing cast, which means it can
silently truncate:

```java
int i = 5;
i += 3.9;     // compiles! i is now 8 — the 3.9 was truncated
```

### No truthiness

```java
int x = 1;
if (x) { }          // ❌ compile error
if (x != 0) { }     // ✅

String s = "";
if (s) { }          // ❌ compile error
if (!s.isEmpty()) { } // ✅
```

Java requires an actual `boolean`. This removes a whole class of JS bug.

### `==` versus `.equals()`

Meet this now, understand it fully in 2.5.

```java
String a = "hello";
String b = "hello";
String c = new String("hello");

IO.println(a == b);        // true   ← same object, from the string pool
IO.println(a == c);        // false  ← different objects
IO.println(a.equals(c));   // true   ← same contents
```

| Operator | Compares |
|---|---|
| `==` | **Identity** — are these the same object? (for primitives: same value) |
| `.equals()` | **Equality** — do these have the same contents? |

> **Rule:** primitives use `==`. Everything else uses `.equals()`. The only common
> exception is enums, where `==` is correct and preferred (2.7).

### Logical operators and short-circuiting

```java
a && b     // short-circuits — if a is false, b never evaluates
a || b     // short-circuits — if a is true, b never evaluates
a & b      // does NOT short-circuit — both always evaluate
a | b      // does NOT short-circuit
```

Short-circuiting is what makes this safe:
```java
if (s != null && s.length() > 0) { }   // ✅ length() only runs if s isn't null
if (s != null & s.length() > 0) { }    // 💥 NPE — & evaluates both sides
```

### Bitwise operators

```java
5 & 3        // 1      AND
5 | 3        // 7      OR
5 ^ 3        // 6      XOR
~5           // -6     NOT
5 << 1       // 10     left shift
-8 >> 1      // -4     arithmetic right shift (keeps sign)
-8 >>> 1     // huge   logical right shift (fills with 0) — Java-specific
```

`>>>` is the one JS also has. You'll mostly meet these in hash functions and
low-level library code.

### The ternary and its surprising typing

```java
String result = (x > 5) ? "big" : "small";
```

The surprise — mixing types makes the compiler find a common type, sometimes badly:

```java
Object o = true ? Integer.valueOf(1) : Double.valueOf(2.0);
IO.println(o);   // 1.0   ← not 1! Both got promoted to double
```

And a classic NPE:
```java
Integer i = null;
int x = true ? i : 0;   // 💥 NPE — the ternary unboxes because 0 is an int
```

### Loops

```java
// classic
for (int i = 0; i < 10; i++) { }

// for-each (Java 5) — use this by default
for (String name : names) { }

// infinite
for (;;) { }

while (condition) { }
do { } while (condition);   // body runs at least once
```

**Labelled break/continue** — for escaping nested loops:

```java
outer:
for (int i = 0; i < 10; i++) {
    for (int j = 0; j < 10; j++) {
        if (grid[i][j] == target) break outer;   // exits BOTH loops
    }
}
```

Rare, but the only clean way to do it in Java (there's no `goto`).

### Old `switch` — and why it caused bugs for twenty years

```java
switch (day) {
    case 1:
        IO.println("Monday");
        // ← no break! Execution FALLS THROUGH into case 2
    case 2:
        IO.println("Tuesday");
        break;
    default:
        IO.println("Other");
}
```

If `day` is 1, this prints **both** "Monday" and "Tuesday". Forgetting `break` was one
of the most common bugs in Java's history.

### Switch expressions `Java 14` — the fix

```java
String name = switch (day) {
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    case 6, 7 -> "Weekend";       // multiple labels
    default -> "Other";
};
```

- **Arrow form** — no fallthrough, ever.
- **It returns a value** — it's an *expression*, so you assign it.
- **Exhaustive** — if it returns a value, the compiler requires every case be covered.

For a multi-statement branch, use a block with `yield`:

```java
int result = switch (op) {
    case "add" -> a + b;
    case "div" -> {
        if (b == 0) throw new ArithmeticException("nope");
        yield a / b;              // yield, not return
    }
    default -> 0;
};
```

### Why switch expressions matter more than they look

> A `switch` that **returns a value** can be checked for **completeness**.

That's the real point. With an enum:

```java
enum Status { ACTIVE, PAUSED, CLOSED }

String label = switch (status) {
    case ACTIVE -> "Running";
    case PAUSED -> "On hold";
    // ❌ compile error: the switch does not cover CLOSED
};
```

No `default` needed — and when someone adds `ARCHIVED` to the enum next year, **every
switch over it stops compiling** until they handle it. The compiler becomes your
migration checklist.

This idea — exhaustiveness — is the foundation of Part 07 (pattern matching) and 2.8
(sealed types). It is the single most useful thing modern Java added.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `7 / 2 == 3.5` | No — `3`. Integer division |
| `-7 % 3 == 2` | No — `-1`. Java keeps the dividend's sign |
| `b += 5` on a `byte` | Compiles, because `+=` hides a cast |
| `if (someInt)` | Compile error. No truthiness |
| `==` on `String` | Sometimes "works" via the string pool, then betrays you |
| Old `switch` without `break` | Falls through silently |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| Colon-form `switch` in new code | Arrow-form switch expression `Java 14` |

---

## Recap

| Concept | One line |
|---|---|
| Integer division | Both ints → int result, remainder discarded |
| No truthiness | Conditions must be `boolean` |
| `==` vs `.equals()` | Identity vs contents |
| `&&` vs `&` | Short-circuits vs always evaluates both |
| Switch expression | Returns a value, no fallthrough, **checked for exhaustiveness** |
