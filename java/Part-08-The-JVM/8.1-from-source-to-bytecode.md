# 8.1 — From source to bytecode

> **What this is:** **Open a class file and look at it.** It stops being mysterious in
> about ten minutes, and everything in Parts 03 and 06 that you took on trust becomes
> something you can verify.

## ⭐ The two-compiler picture

Before anything else, the thing that explains Java's performance behaviour:

```
AHEAD OF TIME — ONCE                    AT RUNTIME — CONTINUOUSLY
─────────────────────                   ──────────────────────────────────────────────

              javac                              hot?           hotter?
  Main.java  ────►  Main.class  ──►  interpreter ──► C1 ──────► C2 ──────► machine code
  what you          bytecode,        slow, starts    quick,      aggressive,
  write             portable         instantly       profiles    optimised
                                          ▲                                │
                                          └──────── deoptimisation ────────┘
                                     an assumption turned out false —
                                     fall back and re-profile
```

> **Java is compiled twice: once by you, then continuously by the JVM using facts only
> available while running.**

That's why a Java service is slow for its first few thousand requests and then several
times faster — and why **a benchmark that doesn't warm up measures nothing** (8.8).

This page is the left-hand side. 8.8 is the right.

## The class file format

```bash
javac Hello.java
xxd Hello.class | head -3
```

```
00000000: cafe babe 0000 0041 001d 0a00 0200 0307  .......A........
```

| Bytes | Meaning |
|---|---|
| `CAFEBABE` | **Magic number.** Every class file starts with it |
| `0000` | Minor version |
| `0041` | Major version — **0x41 = 65 = Java 21** |

**Version numbers you'll meet:**

| Major | Java |
|---|---|
| 52 | 8 |
| 55 | 11 |
| 61 | 17 |
| 65 | 21 |
| 69 | 25 |

> This is what `UnsupportedClassVersionError` is about: *"class file version 65.0, this
> JVM recognises up to 61.0"* means a Java 21 class on a Java 17 JVM. **Java runs older
> class files forever, never newer ones.**

**The rest of the structure:**

```
magic · version · constant pool · access flags · this/super class
      · interfaces · fields · methods · attributes
```

The **constant pool** is the interesting part — every string literal, class name, method
name and type descriptor in the file, stored once and referenced by index. It's why
`javap` output is full of `#7`, `#23` references.

## ⭐ `javap` — your window into everything the compiler did

```bash
javap Hello.class            # public signatures
javap -p Hello.class         # include private members
javap -c Hello.class         # DISASSEMBLE — the bytecode
javap -c -p -v Hello.class   # everything: constant pool, flags, attributes
javap -s Hello.class         # type descriptors
```

**Use this constantly.** It answers "what does this actually compile to?" for every
question in Parts 03, 06 and 07.

## ⭐ The JVM is a stack machine

No registers. Every operation pushes and pops an **operand stack**, and each method frame
has numbered **local variable slots** (8.3).

```java
int add(int a, int b) {
    return a + b;
}
```

```
javap -c:

  0: iload_1        // push local slot 1 (a) onto the operand stack
  1: iload_2        // push local slot 2 (b)
  2: iadd           // pop two ints, add, push the result
  3: ireturn        // pop and return it
```

```
operand stack:   []  →  [a]  →  [a, b]  →  [a+b]  →  []
```

> Slot 0 is `this` for an instance method. That's why `a` is slot 1.

**Reading the opcode names** — the prefix is the type:

| Prefix | Type |
|---|---|
| `i` | int |
| `l` | long |
| `f` | float |
| `d` | double |
| `a` | **reference** ("address") |

So: `iload`/`aload`, `istore`/`astore`, `ireturn`/`areturn`/`return` (void).

### The five invoke instructions

Worth knowing by name — they appear constantly in `javap` output and in stack traces:

| Instruction | Used for |
|---|---|
| `invokestatic` | A `static` method (2.2) |
| `invokevirtual` | A normal instance method — **dynamic dispatch via the vtable** (2.3) |
| `invokespecial` | Constructors, `private` methods, `super.x()` — no dispatch |
| `invokeinterface` | A method through an interface reference |
| **`invokedynamic`** | **Lambdas (6.1), string concatenation (1.3), records' `equals`/`hashCode`/`toString`** |

`invokedynamic` is the one that makes modern Java work: the call target is decided at
**runtime** by a bootstrap method, then cached. That's what lets lambdas exist without a
class file each, and lets the JDK change the implementation strategy without recompiling
your code.

## ⭐ What the compiler desugars

Many things you write are syntax that vanishes before bytecode. Verify each with
`javap -c`:

| You write | Compiles to |
|---|---|
| Enhanced `for` over a collection | `Iterator` + `hasNext` + `next` (5.6) |
| Enhanced `for` over an array | An indexed loop |
| `"a" + b + "c"` | `invokedynamic` → `StringConcatFactory` (1.3) |
| `Integer i = 5` | `Integer.valueOf(5)` (1.1) |
| `int x = someInteger` | `someInteger.intValue()` |
| An `enum` | A final class extending `Enum`, with a `static` array of constants (2.7) |
| A lambda | `invokedynamic` + a private static method (6.1) |
| Inner class access to a private outer field | A synthetic accessor, or `NestMates` in Java 11+ |
| A `record` | A final class + `invokedynamic`-backed `equals`/`hashCode`/`toString` |
| Generics | **Erased** — `Object` plus inserted casts (3.3) |
| String `switch` | Two switches: one on `hashCode`, one on `equals` |

That last one is a fun one to look at:

```java
switch (s) { case "a" -> 1; case "b" -> 2; default -> 0; }
```

compiles to a `lookupswitch` on `s.hashCode()`, then an `equals` check to handle
collisions, then a second `tableswitch` on the resulting index. Three instructions'
worth of source, twenty of bytecode.

## ⭐ Verifying Parts 03 and 06 with your own eyes

This is the exercise that makes this page worth doing.

### Erasure (3.3)

```java
// Erase.java
import java.util.*;
public class Erase {
    List<String> f(List<Integer> in) { return new ArrayList<>(); }
}
```

```bash
javap -s Erase.class
```
```
  java.util.List<java.lang.String> f(java.util.List<java.lang.Integer>);
    descriptor: (Ljava/util/List;)Ljava/util/List;     ← ⭐ no type arguments!
```

The **descriptor** — what the JVM uses — has no generics at all. The full generic type
survives only in a separate `Signature` attribute, which only the *compiler* reads
(`javap -v` shows it).

### Lambdas (6.1)

```java
// Lam.java
public class Lam {
    Runnable r = () -> System.out.println("hi");
}
```

```bash
javac Lam.java && ls *.class
# Lam.class          ← no Lam$1.class
javap -c -p Lam.class
#   invokedynamic #x, 0   // InvokeDynamic #0:run:()Ljava/lang/Runnable;
#   private static void lambda$new$0();
```

Compare with an anonymous class, which produces `Lam$1.class` (2.9).

### Autoboxing (1.1)

```java
Integer i = 5;
```
```
  iconst_5
  invokestatic  Integer.valueOf:(I)Ljava/lang/Integer;    ← the boxing, made visible
```

## The Class-File API `Java 24`

Reading and generating class files **from Java itself**, in the JDK:

```java
import java.lang.classfile.*;

ClassModel cm = ClassFile.of().parse(Path.of("Hello.class"));
cm.methods().forEach(m -> IO.println(m.methodName() + " " + m.methodType()));
```

**Why it exists:** every framework doing bytecode manipulation (Spring, Hibernate, Mockito,
Jacoco) bundled ASM, and each JDK release broke them until ASM caught up. A supported
in-JDK API removes that lag.

> You will rarely use this directly. You benefit from it because your frameworks will stop
> breaking on JDK upgrades.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `UnsupportedClassVersionError` means a missing class | It's a **version** mismatch — newer class file, older JVM |
| Generics are in the bytecode | Only in a `Signature` attribute the JVM ignores |
| Every lambda makes a class file | No — `invokedynamic` |
| Bytecode is what runs | Only at first. Then the JIT compiles it (8.8) |

## Recap

| Concept | One line |
|---|---|
| Two compilers | `javac` once ahead of time; the JIT continuously at runtime |
| `CAFEBABE` | Magic number; next bytes are the class-file version |
| Constant pool | Every literal and name, stored once, referenced by index |
| **Stack machine** | Operand stack + local slots. `iload`, `iadd`, `areturn` |
| Five invokes | `static`, `virtual`, `special`, `interface`, **`dynamic`** |
| `invokedynamic` | Lambdas, string concat, record methods |
| Desugaring | for-each, boxing, enums, records, string switch — all vanish |
| `javap -c -p -v` | **Use it.** It answers "what does this compile to?" |
