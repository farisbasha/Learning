# 8.6 — The collectors

> **What this is:** Four real choices, and **the honest answer that most applications
> should change nothing.**

---

## ⭐ The four (plus one removed)

| Collector | Optimises for | Heap size | Pauses | Flag |
|---|---|---|---|---|
| **Serial** | Footprint, startup | Tiny (<100 MB) | Long | `-XX:+UseSerialGC` |
| **Parallel** | **Throughput** | Any | Long, predictable | `-XX:+UseParallelGC` |
| **G1** | **Balance** | 1 GB – 100s GB | ~50–200 ms | `-XX:+UseG1GC` *(default)* |
| **ZGC** | **Latency** | 1 GB – 16 TB | **< 1 ms** | `-XX:+UseZGC` |
| **Shenandoah** | Latency | Any | < 10 ms | `-XX:+UseShenandoahGC` |
| 💀 **CMS** | — | — | — | **Removed in Java 14** |

---

### Serial

One thread, stop-the-world, copying young + mark-compact old.

**Right when:** a container with **one CPU**, a tiny heap, or a short-lived CLI tool where
startup dominates. Also the default the JVM picks when it detects a single-core machine.

Not a legacy collector — it's the correct choice for its niche, and it has the smallest
footprint of any of them.

### Parallel

Same algorithms as Serial, multi-threaded. **Maximises total throughput** — it does the
least total GC work, at the cost of longer stop-the-world pauses.

**Right when:** batch jobs, data pipelines, anything where total wall-clock time matters
and a 2-second pause doesn't.

> It was the default from Java 5 to 8. Plenty of tuning guides still assume it.

### ⭐ G1 — the default

**Region-based.** The heap is divided into ~2,048 equal regions, each dynamically labelled
eden, survivor, or old:

```
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ E  │ O  │ E  │ S  │ O  │ E  │ O  │ H  │   E=eden S=survivor O=old H=humongous
└────┴────┴────┴────┴────┴────┴────┴────┘
   regions are reassigned as needed — the generations aren't contiguous
```

**"Garbage First"** is the name and the strategy: it tracks how much garbage each region
holds and collects the **emptiest ones first**, getting the most space back for the least
work.

**It's pause-target driven** — you state a goal and G1 chooses how many regions to collect
to meet it:

```bash
-XX:MaxGCPauseMillis=200      # default 200ms — a GOAL, not a guarantee
```

Default since Java 9, and `Java 27` makes it the default on **every machine class**
(previously small/single-core machines got Serial).

> ⚠️ **Humongous objects** — anything larger than half a region (default region size is
> heap/2048) is allocated directly into contiguous old-generation regions. Lots of large
> arrays can fragment G1 badly. Symptom: frequent full GCs with plenty of free heap.
> `-XX:G1HeapRegionSize=32m` can help.

### ⭐ ZGC — sub-millisecond pauses

**Almost everything happens concurrently.** Pauses are **sub-millisecond and do not grow
with heap size** — a 16 TB heap pauses about as long as a 1 GB one.

How: **coloured pointers** and **load barriers**. Metadata bits are stored in unused bits
of the reference itself, and every reference read goes through a barrier that can fix up a
stale pointer on the fly. Objects can be relocated while the application runs.

The cost: **CPU overhead** (barriers on every reference load) and **memory headroom** (it
must keep allocating while collecting).

| Version | Status |
|---|---|
| Java 15 | Production-ready, non-generational |
| `Java 21` | **Generational ZGC** available |
| `Java 23` | **Generational by default** |
| Java 24 | Non-generational mode removed |

> **Use ZGC when p99 latency matters more than throughput** — trading systems, ad bidding,
> interactive services with strict SLAs. Expect ~10–15% lower throughput than G1.

### Shenandoah

Red Hat's concurrent collector — similar goals to ZGC, different implementation (Brooks
forwarding pointers). Low pause, **generational since `Java 25`**.

Ships in most OpenJDK builds. In practice, if you need low pause, ZGC is the more common
choice now.

### 💀 CMS — removed in Java 14

Concurrent Mark Sweep. Deprecated in 9, **removed in 14**.

**You will still find tuning guides for it** — it was *the* low-pause collector from 2004
to 2017, so a decade of blog posts and Stack Overflow answers reference its flags. All of
them are dead:

```bash
-XX:+UseConcMarkSweepGC          # 💀 JVM refuses to start on Java 14+
-XX:CMSInitiatingOccupancyFraction
-XX:+UseParNewGC
```

> Another instance of the 0.3 rule: **check the date on the tuning advice.** If it mentions
> CMS or PermGen (8.3), it predates Java 8.

## ⭐ Reading GC logs

The flags changed in Java 9 — **unified logging**. Old `-XX:+PrintGCDetails` is gone.

```bash
-Xlog:gc                                  # basic
-Xlog:gc*                                 # verbose, everything GC
-Xlog:gc*:file=gc.log:time,uptime,level   # to a file, with timestamps
-Xlog:gc+heap=debug                       # heap sizing detail
-Xlog:safepoint                           # time-to-safepoint (8.5)
```

**Reading a line:**

```
[2.456s][info][gc] GC(12) Pause Young (Normal) (G1 Evacuation Pause) 512M->48M(2048M) 15.234ms
  │        │      │   │     │                                        │    │   │       │
  uptime   level  tag id    what triggered it                        before│  total   duration
                                                                          after
```

**What to look for:**

| Signal | Means |
|---|---|
| `512M->48M` — big drop | Healthy. Most objects died young (8.5) |
| `512M->500M` — small drop | ⚠️ Objects surviving; possible leak or undersized heap |
| Frequent **Pause Full** | ⚠️ Serious — old gen is full |
| After-size creeping up over time | ⚠️ **A leak** (8.7) |
| Pause ≫ reported GC work | ⚠️ **Time to safepoint** (8.5) |

## ⭐ The tuning rule

> **Set a heap size and a pause goal. Measure. Change nothing else without evidence.**

```bash
-Xms4g -Xmx4g                 # equal, to avoid resize pauses (8.3)
-XX:MaxGCPauseMillis=200      # if using G1
-Xlog:gc*:file=gc.log         # so you can actually see what happens
```

**That's it. That's the tuning.**

**Why the caution is warranted:**

- The collectors are **adaptive** — they tune themselves at runtime, and most manual flags
  disable that adaptation
- Most flags **interact** in ways that aren't documented
- Most "GC problems" are actually **application problems** — a leak (8.7), allocating far
  too much, or an undersized heap
- G1 has ~200 flags. The number that help a typical application is approximately **zero**

**The honest diagnostic order:**

1. **Is it actually GC?** Check `-Xlog:gc*`. Often it's safepoints, or not GC at all
2. **Is the heap big enough?** The most common real fix
3. **Is there a leak?** Heap dump (8.9)
4. **Is the application over-allocating?** Profile allocation
5. **Only now** consider a different collector — and change **one flag at a time**

> **In a container, set `-Xmx` explicitly.** The default is ~25% of the container limit
> (8.3), which surprises people far more often than any collector choice.

## Which collector should you actually use?

| Situation | Collector |
|---|---|
| **Almost everything** | **G1 (the default) — change nothing** |
| Strict p99 latency SLA, large heap | ZGC |
| Batch / ETL, throughput is all that matters | Parallel |
| Single-CPU container, tiny heap, CLI tool | Serial |
| You read a blog post about CMS | It doesn't exist |

---

## ⚠️ Traps

| Trap | Reality |
|---|---|
| Copying GC flags from a blog post | They're usually for CMS or Parallel on Java 8 |
| `MaxGCPauseMillis` is a guarantee | It's a **goal**. Set it too low and G1 thrashes |
| ZGC is strictly better | ~10–15% less throughput; more memory headroom |
| Tuning GC will fix the leak | It won't. Find the leak (8.7, 8.9) |
| More flags = better tuned | Each flag disables some adaptive behaviour |
| `-XX:+PrintGCDetails` | Removed in Java 9. Use `-Xlog:gc*` |

## Recap

| Collector | One line |
|---|---|
| **Serial** | One thread, tiny heaps, one CPU |
| **Parallel** | Throughput-first, long pauses — batch work |
| **G1** | Region-based, pause-target driven. **The default. Use it** |
| **ZGC** | Sub-ms pauses, huge heaps, generational by default `Java 23` |
| **Shenandoah** | Low pause, generational `Java 25` |
| 💀 **CMS** | **Removed in 14.** Its tuning guides are everywhere and all dead |
| Logging | `-Xlog:gc*` — the Java 9+ syntax |
| **Tuning** | **Heap size + pause goal. Measure. Nothing else without evidence** |
