# 2.7 — Enums

> **What this is:** Java's enums are **full classes**, not integer aliases. This is more
> powerful than the enums in any language you already know, and most Java developers
> only ever use 10% of them.

---

## Coming from JS/Python/Dart

| Language | Their enum | Java's |
|---|---|---|
| TypeScript | Mostly a numeric or string alias | A real class with fields and methods |
| Python | `Enum` class — closest match | Similar, plus per-constant method bodies |
| PHP 8.1 | Backed enums — close | Java's can do more |
| Dart | Enhanced enums (2.17+) — very close | Same idea |

If your mental model is "a named number", throw it away. A Java enum constant is a
**singleton object instance**.

---

## The concepts

### Basic constants

```java
public enum Status {
    ACTIVE, PAUSED, CLOSED
}
```

Each constant is a `public static final` instance of `Status`. There are exactly three
`Status` objects in the JVM, ever.

### The built-in methods

```java
Status.values()               // Status[] {ACTIVE, PAUSED, CLOSED} — a fresh copy each call
Status.valueOf("ACTIVE")      // ACTIVE — throws IllegalArgumentException if no match
Status.ACTIVE.name()          // "ACTIVE" — the declared name, never changes
Status.ACTIVE.ordinal()       // 0 — declaration position
Status.ACTIVE.compareTo(...)  // by ordinal
```

### ⚠️ Why depending on `ordinal()` is fragile

```java
// ❌ storing the ordinal in a database
db.save(status.ordinal());     // saves 0, 1 or 2
```

Now someone inserts a constant:

```java
public enum Status {
    DRAFT,              // ← added at the top
    ACTIVE, PAUSED, CLOSED
}
```

Every stored `0` now means `DRAFT` instead of `ACTIVE`. **Your entire database silently
shifted by one.**

```java
// ✅ persist the name
db.save(status.name());
Status.valueOf(row.getString("status"));

// ✅ or an explicit code that you control
public enum Status {
    ACTIVE("A"), PAUSED("P"), CLOSED("C");
    private final String code;
    Status(String code) { this.code = code; }
    public String code() { return code; }
}
```

> **Rule: `ordinal()` is for the JVM's internal use (`EnumMap`, `EnumSet`). Never store
> it, never expose it, never switch on it.**

### Enums with fields, constructors and methods

```java
public enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    VENUS  (4.869e+24, 6.0518e6),
    EARTH  (5.976e+24, 6.37814e6);        // ← semicolon required before other members

    private final double mass;
    private final double radius;

    Planet(double mass, double radius) {   // constructor is implicitly private
        this.mass = mass;
        this.radius = radius;
    }

    public double surfaceGravity() {
        return 6.67300E-11 * mass / (radius * radius);
    }
}

IO.println(Planet.EARTH.surfaceGravity());    // 9.80...
```

The constructor is **always private** — you cannot create new constants at runtime, which
is what makes the set genuinely closed.

### ⭐ Constant-specific bodies — the strategy pattern with no ceremony

This is the feature most people never discover.

```java
public enum Operation {
    PLUS  { public int apply(int a, int b) { return a + b; } },
    MINUS { public int apply(int a, int b) { return a - b; } },
    TIMES { public int apply(int a, int b) { return a * b; } },
    DIVIDE {
        public int apply(int a, int b) {
            if (b == 0) throw new ArithmeticException("divide by zero");
            return a / b;
        }
    };

    public abstract int apply(int a, int b);
}

Operation.PLUS.apply(3, 4);     // 7
Operation.TIMES.apply(3, 4);    // 12
```

Each constant **overrides** the abstract method with its own body. Compare it to the
classical version:

```java
// the same thing, pre-enum: an interface, four classes, a registry
interface Operation { int apply(int a, int b); }
class Plus implements Operation { ... }
class Minus implements Operation { ... }
class Times implements Operation { ... }
class Divide implements Operation { ... }
Map<String, Operation> registry = Map.of("+", new Plus(), ...);
```

Five files and a lookup map, versus one enum. **That's the strategy pattern with zero
ceremony**, and it's the single best reason to know enums properly.

Behind the scenes each constant with a body becomes an anonymous subclass —
`Operation$1`, `Operation$2` (1.7, 2.9).

### Enums implementing interfaces

```java
public interface Describable { String describe(); }

public enum Status implements Describable {
    ACTIVE  { public String describe() { return "Currently running"; } },
    PAUSED  { public String describe() { return "Temporarily stopped"; } },
    CLOSED  { public String describe() { return "Finished"; } };
}
```

Or share one implementation using a field:

```java
public enum Status implements Describable {
    ACTIVE("Currently running"),
    PAUSED("Temporarily stopped");

    private final String description;
    Status(String d) { this.description = d; }
    @Override public String describe() { return description; }
}
```

### `EnumMap` and `EnumSet` — the fast collections nobody discovers

```java
import java.util.EnumMap;
import java.util.EnumSet;

// EnumMap — backed by a plain ARRAY indexed by ordinal
Map<Status, Integer> counts = new EnumMap<>(Status.class);
counts.put(Status.ACTIVE, 5);

// EnumSet — backed by a single long BITMASK (for ≤ 64 constants)
Set<Status> open = EnumSet.of(Status.ACTIVE, Status.PAUSED);
EnumSet.allOf(Status.class);
EnumSet.noneOf(Status.class);
EnumSet.range(Status.ACTIVE, Status.CLOSED);
EnumSet.complementOf(open);          // everything NOT in `open`
```

**Why they're dramatically faster:**

| | `HashMap`/`HashSet` | `EnumMap`/`EnumSet` |
|---|---|---|
| Storage | Bucket array + `Node` objects + hashing | A plain array / **one `long`** |
| Lookup | Hash, mask, walk the bucket, `equals` | Direct array index |
| Memory | ~48 bytes per entry | ~4 bytes, or a single bit |
| Iteration order | Unspecified | **Declaration order**, guaranteed |

`EnumSet.of(A, B)` for an enum with 5 constants is literally the number `0b00011` in a
single `long`. Union, intersection and complement are one CPU instruction each.

> **Rule: if the key type is an enum, use `EnumMap`/`EnumSet`. Always. There is no
> downside.**

### `switch` over enums, and exhaustiveness

```java
String label = switch (status) {
    case ACTIVE -> "Running";
    case PAUSED -> "On hold";
    case CLOSED -> "Done";
};                                     // no default needed — the compiler knows it's complete
```

Note you write `ACTIVE`, not `Status.ACTIVE` — the type is already known.

**The important part: leave out `default`.**

```java
// ❌ with a default, adding a constant silently falls through
String label = switch (status) {
    case ACTIVE -> "Running";
    default -> "Other";           // ADDING a constant → silently becomes "Other"
};

// ✅ without a default, adding a constant BREAKS THE BUILD until you handle it
String label = switch (status) {
    case ACTIVE -> "Running";
    case PAUSED -> "On hold";
    case CLOSED -> "Done";
};
```

> **This is the payoff described in 1.2.** Omit `default` on enum switches, and the
> compiler becomes your migration checklist every time the enum grows.

### ⭐ The enum singleton — the safest singleton in Java

```java
public enum Registry {
    INSTANCE;

    private final Map<String, String> data = new ConcurrentHashMap<>();

    public void put(String k, String v) { data.put(k, v); }
    public String get(String k)         { return data.get(k); }
}

Registry.INSTANCE.put("a", "b");
```

Compare with the hand-rolled version:

```java
// the classic, and everything that can go wrong with it
public class Registry {
    private static Registry instance;
    private Registry() { }
    public static Registry getInstance() {
        if (instance == null) instance = new Registry();   // ❌ race condition
        return instance;
    }
}
```

The hand-rolled singleton has to defend against:

| Attack | Enum's answer |
|---|---|
| Two threads racing in `getInstance()` | Class initialisation is **guaranteed thread-safe by the JVM** (2.2, 8.2) |
| Reflection calling the private constructor | The JVM **forbids** reflective enum instantiation |
| Deserialization creating a second instance | Enums have **special serialization** — always resolve to the existing constant |
| Cloning | Enums cannot be cloned |

You get all four for free, in three lines. This is *Effective Java*'s recommended
singleton, and it's the right default.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| Storing `ordinal()` | Reordering constants corrupts your data |
| `default` in an enum switch | Defeats exhaustiveness checking |
| `HashMap<Status, X>` | Use `EnumMap` — faster and ordered |
| `valueOf("active")` | Case-sensitive. Throws `IllegalArgumentException` |
| `values()` in a hot loop | Returns a **fresh array copy** every call. Cache it |
| Expecting to add constants at runtime | The set is closed. That's the point |

That `values()` one:

```java
// ❌ allocates a new array on every iteration
for (int i = 0; i < 1_000_000; i++) { Status s = Status.values()[0]; }

// ✅
private static final Status[] VALUES = Status.values();
```

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `public static final int STATUS_ACTIVE = 0;` (the int-constant pattern) | An enum |
| Storing ordinals | Store `name()` or an explicit code |
| Double-checked-locking singletons | `enum Singleton { INSTANCE; }` |

---

## Recap

| Concept | One line |
|---|---|
| Enums are classes | Fields, constructors, methods, interfaces — all allowed |
| Constant-specific bodies | Strategy pattern with no ceremony |
| `ordinal()` | Internal only. Never persist it |
| `EnumMap` / `EnumSet` | Array- and bitmask-backed. Always use them for enum keys |
| Switch with no `default` | Compiler enforces you handle new constants |
| `enum X { INSTANCE; }` | The safest singleton: thread-safe, reflection-proof, serialization-proof |
