# 2.9 — Nested, inner and anonymous classes

> **What this is:** **Four different things with confusingly similar names.** You need
> them mostly to *read* older code — lambdas replaced most of their uses — but one of
> them causes a real memory leak, and that's worth knowing.

---

## Coming from JS/Python/Dart

The closest thing you know is a **closure**. An anonymous class is what Java had *instead
of* closures from 1997 to 2014, and it's why pre-Java-8 code is so noisy.

```javascript
// JS
button.addEventListener("click", () => console.log("clicked"));
```

```java
// Java 1.1 – 7. Same meaning.
button.addActionListener(new ActionListener() {
    @Override public void actionPerformed(ActionEvent e) {
        System.out.println("clicked");
    }
});
```

```java
// Java 8+
button.addActionListener(e -> IO.println("clicked"));
```

---

## The four kinds, at a glance

| Kind | Declared | Holds a reference to the outer instance? | Compiles to |
|---|---|---|---|
| **Static nested** | `static class` inside a class | ❌ No | `Outer$Nested.class` |
| **Inner** | `class` inside a class | ✅ **Yes** — the leak risk | `Outer$Inner.class` |
| **Local** | Inside a method body | ✅ Yes (if non-static context) | `Outer$1Local.class` |
| **Anonymous** | `new Thing() { ... }` | ✅ Yes | `Outer$1.class` |

---

## 1. Static nested classes

Just a class **namespaced** inside another. No link to any instance.

```java
public class Outer {
    private static int counter;

    public static class Nested {           // static
        void doThing() {
            counter++;                      // ✅ can see outer STATIC members
            // outerField;                  // ❌ cannot see outer INSTANCE members
        }
    }
}

var n = new Outer.Nested();                 // no Outer instance needed
```

**Use it when** a helper type only makes sense in the context of the outer class:

```java
public class HashMap<K,V> {
    static class Node<K,V> { ... }         // this is real JDK code
}

public class Server {
    public record Config(int port, String host) { }    // records are implicitly static
}
```

> Nested records, enums and interfaces are **always implicitly static**. You never write
> the keyword for them.

## 2. Inner classes — and the memory leak

```java
public class Outer {
    private String name = "outer";

    public class Inner {                    // NO static keyword
        void show() {
            IO.println(name);               // ✅ can see outer INSTANCE fields
            IO.println(Outer.this.name);     // the explicit form
        }
    }
}

Outer o = new Outer();
Outer.Inner i = o.new Inner();              // ← weird syntax; needs an Outer instance
```

### What it costs

Every inner class instance holds a **hidden field** pointing at its enclosing instance:

```java
// what the compiler actually generates
class Outer$Inner {
    final Outer this$0;                     // ← the hidden reference
    Outer$Inner(Outer outer) { this.this$0 = outer; }
}
```

You can see it:
```bash
javap -p Outer\$Inner.class
```

### The leak

```java
public class BigService {
    private final byte[] cache = new byte[100_000_000];    // 100MB

    public Runnable makeTask() {
        return new Runnable() {                            // anonymous = inner
            @Override public void run() { IO.println("done"); }
        };
    }
}

var service = new BigService();
Runnable task = service.makeTask();
service = null;                            // we're finished with the service...
scheduler.schedule(task, 1, DAYS);         // ...but the task holds it alive
```

`task` doesn't use anything from `BigService`, but it still holds `this$0` → the whole
`BigService` → the 100MB array. **It cannot be garbage collected** for as long as the
task lives. (Part 08 covers reachability in detail.)

**Fix — make it static:**

```java
private static class Task implements Runnable {            // static — no this$0
    @Override public void run() { IO.println("done"); }
}
public Runnable makeTask() { return new Task(); }
```

> **The rule: make every nested class `static` unless it genuinely needs the outer
> instance.** IntelliJ and SpotBugs both warn about this, and they're right.

This is the classic Android memory leak too — a non-static inner `Handler` or
`AsyncTask` holding an `Activity` alive through a screen rotation.

## 3. Local classes

Declared inside a method body. Rare.

```java
void process(List<String> items) {
    class Counter {                        // local to this method
        int count;
        void inc() { count++; }
    }

    var c = new Counter();
    items.forEach(s -> c.inc());
}
```

Mostly superseded by **local records** (2.6), which are cleaner for the common case of
"I need a temporary type here".

---

## 4. Anonymous classes

Declare and instantiate in one expression.

```java
Comparator<String> byLength = new Comparator<String>() {
    @Override public int compare(String a, String b) {
        return Integer.compare(a.length(), b.length());
    }
};
```

**Still needed when** — and this is the useful part, because people assume lambdas
replaced them entirely:

**(a) More than one method to implement:**
```java
// Can't be a lambda — two abstract methods
var listener = new MouseListener() {
    @Override public void mousePressed(MouseEvent e)  { ... }
    @Override public void mouseReleased(MouseEvent e) { ... }
    // ...
};
```

**(b) You need state:**
```java
var counter = new Runnable() {
    private int count;                     // lambdas cannot have fields
    @Override public void run() { count++; }
};
```

**(c) Extending a class (not implementing an interface):**
```java
var t = new Thread() {                     // Thread is a class
    @Override public void run() { ... }
};
```

**(d) Anonymous subclass to capture a generic type** — the "super type token" trick that
JSON libraries use to beat erasure (Part 03.5):
```java
var type = new TypeReference<List<User>>() { };   // Jackson
```

## ⭐ Variable capture and "effectively final"

All of these — and lambdas — can only capture variables that are **effectively final**
(1.1).

```java
void f() {
    int x = 5;                             // never reassigned → effectively final
    Runnable r = () -> IO.println(x);      // ✅

    int y = 5;
    y = 6;                                 // reassigned
    Runnable r2 = () -> IO.println(y);     // ❌ must be final or effectively final
}
```

**Why the restriction:** the captured value is **copied** into the inner class/lambda at
creation. If `y` changed afterwards, the copy and the original would disagree, and there'd
be no sensible answer to which one you meant. (JavaScript's closures capture the *variable*,
not the value — which is exactly why `var` in a loop is the classic JS bug from your
Node notes.)

**The workaround when you genuinely need mutation:**

```java
// ❌ won't compile
int count = 0;
items.forEach(i -> count++);

// ✅ mutate the contents of an effectively-final holder
var count = new AtomicInteger();
items.forEach(i -> count.incrementAndGet());

// ✅ or, usually better, don't mutate at all
long count = items.stream().filter(...).count();
```

**Instance fields are NOT restricted** — only locals:
```java
class C {
    private int count;                     // a field
    void f() {
        Runnable r = () -> count++;        // ✅ fine — `this` is what's captured
    }
}
```

## What each compiles to

```java
public class Outer {
    static class Nested { }                // → Outer$Nested.class
    class Inner { }                        // → Outer$Inner.class
    void f() {
        class Local { }                    // → Outer$1Local.class
        Runnable r = new Runnable() {      // → Outer$1.class
            public void run() { }
        };
    }
}
```

```bash
javac Outer.java && ls *.class
# Outer.class  Outer$Nested.class  Outer$Inner.class  Outer$1Local.class  Outer$1.class
```

> **Read stack traces with this in mind.** `com.example.Outer$1.run(Outer.java:14)` tells
> you the frame is inside the *first anonymous class* declared in `Outer` — useful when
> you're staring at a trace wondering where the code is.

### ⚠️ Lambdas do NOT generate a class file

```java
Runnable r = () -> IO.println("hi");
```

This produces **no** `Outer$1.class`. Lambdas compile to an `invokedynamic` instruction
plus a private static method (`lambda$f$0`), and the JVM spins up the implementation at
runtime. That's why lambdas are cheaper than anonymous classes — one fewer class to load
and verify (8.2). Full story in 6.1.

## Which of these lambdas replaced, and which they did not

| Use case | Now |
|---|---|
| Single-method callback | **Lambda** |
| `Comparator` | **Lambda** or `Comparator.comparing()` |
| `Runnable` / `Callable` | **Lambda** |
| Multi-method listener | Still an anonymous class |
| Needs instance state | Still an anonymous class |
| Extending a class | Still an anonymous class |
| Type tokens (`new TypeReference<>(){}`) | Still an anonymous class |
| Helper type scoped to a class | **Static nested class** or nested record |
| Temporary type inside a method | **Local record** (2.6) |

## ⚠️ Traps

| Trap | Reality |
|---|---|
| Non-static inner class | Holds the outer instance alive — memory leak |
| `new Outer.Inner()` | Wrong. It's `outer.new Inner()` |
| Mutating a captured local | Must be effectively final. Use `AtomicInteger` or restructure |
| Expecting a `.class` file for a lambda | There isn't one — `invokedynamic` |
| `this` inside an anonymous class | Refers to the **anonymous** instance. Use `Outer.this` |

That last one:

```java
public class Outer {
    private String name = "outer";
    void f() {
        Runnable r = new Runnable() {
            public void run() {
                // this.name          ← ❌ the anonymous class has no `name`
                IO.println(Outer.this.name);   // ✅
            }
        };
    }
}
```

Inside a **lambda**, `this` refers to the enclosing instance — which is another reason
lambdas are less confusing.

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| Anonymous class for a single-method interface | Lambda |
| Non-static inner class by default | `static` nested class |
| Local class | Local record (2.6) |
| Double-brace initialisation `new ArrayList<>(){{ add("a"); }}` | `List.of(...)` — the double-brace idiom creates an anonymous subclass and leaks the outer instance |

---

## Recap

| Kind | Key fact |
|---|---|
| **Static nested** | Just namespacing. **Default choice.** No outer reference |
| **Inner** | Hidden `this$0` → memory leak risk |
| **Local** | Method-scoped. Use a local record instead |
| **Anonymous** | Pre-lambda closures; still needed for multi-method, state, or extending a class |
| Capture | Locals must be **effectively final**; fields are unrestricted |
| Compiles to | `Outer$Nested`, `Outer$Inner`, `Outer$1` — lambdas produce **no class file** |
