# 13.1 — Read the JDK's own source

> **What this is:** **It ships with your JDK.** It is well written, heavily reviewed, and
> full of comments explaining trade-offs. This is the fastest remaining way to improve.

---

## Where it is

```bash
$JAVA_HOME/lib/src.zip
```

```bash
unzip -l $(/usr/libexec/java_home)/lib/src.zip | head
```

**In an IDE:** Ctrl/Cmd-click any JDK class and it opens. That's it — no setup.

**Online:** [github.com/openjdk/jdk](https://github.com/openjdk/jdk) — `src/java.base/share/classes/`

## ⭐ The reading order

**Start here** — small, complete, immediately useful:

| # | Class | Why | Ties to |
|---|---|---|---|
| 1 | **`Objects`** | ~100 lines. `requireNonNull`, `equals`, `hash`. See how carefully trivial code is written | 2.5, 4.4 |
| 2 | **`Optional`** | Small and complete. Notice it is **not `Serializable`** — a design statement | 6.7, 10.5 |
| 3 | **`ArrayList`** | ⭐ The growth policy, `System.arraycopy`, `modCount`, the contained unchecked cast | 5.2, 5.6, 3.5 |
| 4 | **`AbstractList`** | The skeletal-implementation pattern; where `modCount` lives | 2.4, 5.6 |
| 5 | **`HashMap`** | ⭐ The `hash()` spreading function, treeification, resize. **The best 500 lines in the JDK** | 5.3, 2.5 |
| 6 | **`String`** | Compact strings, the pool, why it's `final` | 1.3, 2.3 |

**Then the concurrency layer** — harder, and worth it:

| Class | Why | Ties to |
|---|---|---|
| **`ConcurrentHashMap`** | CAS on empty bins, per-bin locking, why `size()` is approximate | 9.7, 9.6 |
| **`ReentrantLock`** | A thin wrapper over AQS — the interesting part is `Sync` | 9.5 |
| ⭐ **`AbstractQueuedSynchronizer`** | ~2,000 lines that make **every** synchroniser stop being magic | 9.5, 9.10 |
| **`ThreadPoolExecutor`** | ⭐ The `execute()` method is the core→queue→max→reject logic from 9.8 | 9.8 |
| **`CompletableFuture`** | ~3,000 lines. Dense. Read `thenApply`/`thenCompose` | 9.9 |

**Then the stream machinery** — the deepest corner:

| Class | Why | Ties to |
|---|---|---|
| **`AbstractPipeline`** | ⭐ How laziness is actually implemented — the stage chain | 6.4 |
| **`Collectors`** | Supplier/accumulator/combiner/finisher, forty times over | 6.6 |
| **`Spliterator`** | `trySplit` and the characteristics flags | 6.8 |

> ⭐ **`ThreadPoolExecutor.execute()` is the single highest-value method to read.** It's
> ~30 lines and it makes the surprising parameter interaction from 9.8 — queue fills
> *before* the pool grows — completely obvious.

## ⭐ What to look for

Reading source without knowing what you're looking for is just scrolling. Look for these
five things:

### 1. Invariants stated in comments

```java
// java.util.ArrayList
/**
 * Shared empty array instance used for default sized empty instances. We
 * distinguish this from EMPTY_ELEMENTDATA to know how much to inflate when
 * first element is added.
 */
private static final Object[] DEFAULTCAPACITY_EMPTY_ELEMENTDATA = {};
```

**Two empty arrays that look identical, for a reason the comment explains.** The JDK
documents *why*, not *what* — exactly what 12.1 said good Javadoc does.

### 2. Defensive copies

```java
// java.util.Collections
public static <T> List<T> unmodifiableList(List<? extends T> list) {
    return new UnmodifiableList<>(list);    // ⭐ a VIEW — not a copy (5.7)
}
```

Notice where the JDK copies and where it deliberately doesn't (2.10, 5.7). The distinction
is always intentional and usually documented.

### 3. ⭐ Fast paths

```java
// java.lang.String
public boolean equals(Object anObject) {
    if (this == anObject) return true;             // ⭐ identity first
    return (anObject instanceof String aString)
        && (!COMPACT_STRINGS || this.coder == aString.coder)   // ⭐ cheap check
        && StringLatin1.equals(value, aString.value);          // then the real work
}
```

**Cheapest check first, always.** This shape — identity, then a cheap discriminator, then
the expensive comparison — is everywhere, and it's the pattern to copy in your own
`equals` (2.5).

```java
// java.util.ArrayList.addAll — bulk copy, NOT a loop of add() (this is 2.3's fragile base class!)
System.arraycopy(a, 0, elementData, s, numNew);
```

### 4. ⭐ `@SuppressWarnings` with an explanation

```java
// java.util.ArrayList
@SuppressWarnings("unchecked")
E elementData(int index) {
    return (E) elementData[index];        // safe: only E is ever stored here (3.3, 3.5)
}
```

**Narrowest possible scope, and a reason.** This is the standard 3.3 tells you to hold
yourself to — the JDK does it consistently.

### 5. The `Integer` cache, and other things you now recognise

```java
// java.lang.Integer
public static Integer valueOf(int i) {
    if (i >= IntegerCache.low && i <= IntegerCache.high)
        return IntegerCache.cache[i + (-IntegerCache.low)];     // ⭐ the 1.1 trap, in source
    return new Integer(i);
}
```

> **The experience worth having:** you'll open a class expecting magic and find ordinary
> Java, written carefully, by people solving the same problems you have. **There is no
> magic layer.** That realisation is the actual payoff of this step.

## ⭐ Reading a JEP

**JEPs are the design documents for every feature in this roadmap** — and the best writing
about Java that exists.

**Index:** [openjdk.org/jeps/0](https://openjdk.org/jeps/0)

**The structure is always the same:** Summary → Goals → **Non-Goals** → **Motivation** →
Description → **Alternatives** → Risks.

> ⭐ **Read "Non-Goals" and "Alternatives" first.** They tell you what the designers
> deliberately *refused* to do and why — which is where the actual reasoning is, and it's
> the part no blog post ever covers.

**The ones worth reading, mapped to this roadmap:**

| JEP | Feature | Part |
|---|---|---|
| **395** | Records | 2.6 |
| **409** | Sealed classes | 2.8 |
| **441** | Pattern matching for switch | 7.2 |
| ⭐ **444** | **Virtual threads** | 9.11 |
| **400** | UTF-8 by default | 10.2 |
| ⭐ **425/436/444** | The Loom progression | 9.11 |
| **454** | Foreign Function & Memory | 11.9 |
| **261** | The module system | 11.10 |

> **JEP 444 (virtual threads) is the single best one to read.** Its Motivation section
> explains the entire thread-per-request vs async argument — everything 9.8, 9.9 and 9.11
> cover — better and more concisely than any secondary source.

**Also:** [inside.java](https://inside.java) for the JDK team's own writing, and the
`-dev` mailing lists if you want to watch decisions being made.

## A practical exercise

Pick one question you still have, and answer it from source:

| Question | Read |
|---|---|
| Why is `HashMap`'s default capacity 16? | `HashMap` — the constants and their comments |
| What does `ArrayList` grow by? | `ArrayList.grow()` |
| How does `ThreadPoolExecutor` decide to make a thread? | `execute()` |
| Why is `Optional` not `Serializable`? | The class declaration + JEP/mailing list |
| How does a stream stay lazy? | `AbstractPipeline` |

> **Thirty minutes in `HashMap` teaches more than a week of articles about it.**
