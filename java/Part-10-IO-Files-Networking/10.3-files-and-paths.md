# 10.3 — Files and paths

> **What this is:** **NIO.2 replaced `java.io.File` comprehensively.** Use it for
> everything new. `Java 7`

---

## `Path` — the replacement for `File`

```java
Path p = Path.of("/home/basha/notes.md");        // Java 11 — preferred
Path p = Paths.get("/home/basha/notes.md");      // Java 7 — the older spelling

Path rel = Path.of("data", "input.csv");         // data/input.csv, platform separators
```

```java
p.getFileName();        // notes.md
p.getParent();          // /home/basha
p.getRoot();            // /
p.toAbsolutePath();
p.isAbsolute();

base.resolve("sub/file.txt");       // ⭐ join — base/sub/file.txt
base.resolveSibling("other.txt");   // replace the last element
base.relativize(other);             // ⭐ the path FROM base TO other
p.normalize();                      // ⭐ collapse . and ..
```

> ⭐ **`resolve` is how you join paths.** Never concatenate with `"/"` — it breaks on
> Windows and mishandles absolute arguments.
>
> ⚠️ **`resolve` with an absolute argument returns that argument**, discarding the base.
> That's the correct POSIX behaviour and a real path-traversal risk:
> ```java
> Path unsafe = uploadDir.resolve(userInput);      // userInput = "/etc/passwd" → /etc/passwd
> Path safe = uploadDir.resolve(userInput).normalize();
> if (!safe.startsWith(uploadDir)) throw new SecurityException();   // ✅ validate
> ```

**A `Path` is just a name.** It doesn't have to exist — creating one touches no disk.

## ⭐ `Files` — the utility class that does nearly everything

```java
// text — these default to UTF-8 on every platform and version (10.2)
String s = Files.readString(path);                     // Java 11
Files.writeString(path, content);                      // Java 11
List<String> lines = Files.readAllLines(path);

// bytes
byte[] b = Files.readAllBytes(path);
Files.write(path, bytes);

// existence and type
Files.exists(path);  Files.notExists(path);  Files.isDirectory(path);
Files.isRegularFile(path);  Files.isReadable(path);  Files.size(path);

// manipulation
Files.copy(src, dst, StandardCopyOption.REPLACE_EXISTING);
Files.move(src, dst, StandardCopyOption.ATOMIC_MOVE);
Files.delete(path);                    // throws if missing
Files.deleteIfExists(path);            // doesn't
Files.createDirectories(path);         // ⭐ creates parents, no error if it exists
Files.createTempFile("prefix", ".tmp");

// open options
Files.writeString(path, s, StandardOpenOption.APPEND);
Files.newBufferedReader(path);         // UTF-8 (10.1)
Files.newOutputStream(path);
```

> ⚠️ **`Files.exists()` then open is a TOCTOU race** — the file can vanish between the two
> calls. Just open it and catch `NoSuchFileException` (4.4).

---

## ⚠️ Streams from `Files` must be closed

```java
// ❌ leaks a file handle (8.7)
Files.lines(path).filter(...).toList();

// ✅ try-with-resources (4.3)
try (var lines = Files.lines(path)) {
    return lines.filter(...).toList();
}
```

`Files.lines`, `Files.walk`, `Files.list` and `Files.find` all return **`Stream`s backed by
an open file handle** (6.4). They implement `AutoCloseable`, and they are the *only*
streams you routinely need to close.

> `Files.readAllLines` reads eagerly into a `List` and needs no closing — use it for small
> files, `Files.lines` for large ones.

## Walking trees

```java
// one level
try (var s = Files.list(dir)) { ... }

// recursive
try (var s = Files.walk(dir)) {
    s.filter(Files::isRegularFile)
     .filter(p -> p.toString().endsWith(".java"))
     .forEach(IO::println);
}

try (var s = Files.walk(dir, 3)) { ... }          // max depth

try (var s = Files.find(dir, Integer.MAX_VALUE,
        (p, attrs) -> attrs.isRegularFile() && attrs.size() > 1_000_000)) { ... }
```

**`walkFileTree` + a visitor** — for when you need full control (pre/post-order, error
handling, pruning):

```java
Files.walkFileTree(dir, new SimpleFileVisitor<Path>() {
    @Override public FileVisitResult visitFile(Path f, BasicFileAttributes a) {
        Files.delete(f);
        return FileVisitResult.CONTINUE;
    }
    @Override public FileVisitResult postVisitDirectory(Path d, IOException e) throws IOException {
        Files.delete(d);                          // ⭐ AFTER its contents — recursive delete
        return FileVisitResult.CONTINUE;
    }
    @Override public FileVisitResult visitFileFailed(Path f, IOException e) {
        return FileVisitResult.CONTINUE;          // skip unreadable files
    }
});
```

Return `SKIP_SUBTREE` to prune, `TERMINATE` to stop.

## Attributes, permissions, symbolic links

```java
var attrs = Files.readAttributes(path, BasicFileAttributes.class);
attrs.creationTime(); attrs.lastModifiedTime(); attrs.size(); attrs.isSymbolicLink();

// POSIX-specific — throws UnsupportedOperationException on Windows
var perms = Files.getPosixFilePermissions(path);
Files.setPosixFilePermissions(path, PosixFilePermissions.fromString("rw-r--r--"));

Files.isSymbolicLink(path);
Files.readSymbolicLink(path);
Files.createSymbolicLink(link, target);
```

By default `Files` methods **follow** symlinks; pass `LinkOption.NOFOLLOW_LINKS` not to.

## ⭐ Writing a file safely

**The problem:** a crash or a concurrent reader mid-write leaves a truncated file.

```java
// ❌ a reader can see a half-written file; a crash leaves it corrupt
Files.writeString(target, content);

// ✅ write to a temp file in the SAME directory, then atomically rename
Path tmp = Files.createTempFile(target.getParent(), "tmp", ".partial");
try {
    Files.writeString(tmp, content);
    Files.move(tmp, target,
        StandardCopyOption.REPLACE_EXISTING,
        StandardCopyOption.ATOMIC_MOVE);          // ⭐ atomic
} catch (IOException e) {
    Files.deleteIfExists(tmp);
    throw e;
}
```

> ⭐ **A rename within one filesystem is atomic** — readers see either the old file or the
> new one, never a partial write. **The temp file must be in the same directory**, or the
> "move" becomes a copy+delete and loses atomicity (and `ATOMIC_MOVE` throws).

This is how every config writer, cache and atomic-save feature works.

## `WatchService` — change notifications

```java
try (var watcher = FileSystems.getDefault().newWatchService()) {
    dir.register(watcher, ENTRY_CREATE, ENTRY_MODIFY, ENTRY_DELETE);

    while (true) {
        WatchKey key = watcher.take();            // blocks (9.7)
        for (WatchEvent<?> event : key.pollEvents()) {
            IO.println(event.kind() + ": " + event.context());
        }
        if (!key.reset()) break;
    }
}
```

⚠️ Not recursive (register each directory), can drop events under load (`OVERFLOW`), and
on macOS it **polls** rather than using native notifications, so it's slow. For anything
serious, use a library.

## ⭐ Classpath resources versus filesystem paths

**A very common source of "works in the IDE, fails in production".**

```java
// ❌ works in the IDE, fails inside a JAR
Path p = Path.of("src/main/resources/config.json");
String s = Files.readString(p);
```

In the IDE the working directory is the project root and the file is on disk. **Packaged
into a JAR, that file is an entry inside a zip** (1.6) — there is no filesystem path to it.

```java
// ✅ read it as a classpath resource — works both ways
try (var in = MyClass.class.getResourceAsStream("/config.json")) {
    if (in == null) throw new IllegalStateException("config.json not on the classpath");
    String s = new String(in.readAllBytes(), StandardCharsets.UTF_8);   // (10.1, 10.2)
}
```

| Form | Resolves |
|---|---|
| `getResourceAsStream("/config.json")` | From the **classpath root** |
| `getResourceAsStream("config.json")` | Relative to **that class's package** |
| `getClassLoader().getResourceAsStream("config.json")` | Classpath root (no leading `/`) |

> **The rule: bundled files are *resources*, not *paths*.** Anything in `src/main/resources`
> must be read with `getResourceAsStream`, never `Path.of`. Use `Path` only for files that
> genuinely live on the deployment machine's disk.

⚠️ You also cannot get a working `File` or `Path` for a resource inside a JAR — if a
library demands one, copy the resource to a temp file first.

## 💀 `java.io.File` — legacy, and its silent-failure API

```java
File f = new File("data.txt");
f.delete();        // 💀 returns BOOLEAN. Fails silently. Why? No idea.
f.mkdir();         // 💀 same
f.renameTo(other); // 💀 same
f.length();        // 💀 returns 0 for "doesn't exist" AND for "empty file"
```

**The design flaw: errors are `boolean`, not exceptions.** You get no reason, and almost
nobody checks the return value.

```java
// ✅ NIO.2 throws, with a reason
Files.delete(path);
// → NoSuchFileException / DirectoryNotEmptyException / AccessDeniedException
```

Plus NIO.2 adds symlinks, file attributes, permissions, atomic moves, `WatchService`, and
pluggable filesystems (including reading **inside a ZIP as a filesystem**).

```java
File f = path.toFile();       // bridges, when a legacy API demands it
Path p = file.toPath();
```

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `Files.lines`/`walk` without try-with-resources | Leaks a file handle |
| `Path.of("src/main/resources/...")` | Fails inside a JAR. Use `getResourceAsStream` |
| Concatenating paths with `"/"` | Use `resolve` |
| `resolve(userInput)` where input is absolute | Path traversal. `normalize` + `startsWith` check |
| `exists()` then open | TOCTOU race |
| Temp file in a different directory | `ATOMIC_MOVE` fails |
| `File.delete()` returning false | Silently ignored. Use `Files.delete` |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `java.io.File` in new code | `java.nio.file.Path` + `Files` |
| `new FileReader/FileWriter` | `Files.newBufferedReader/Writer` (UTF-8, 10.2) |
| `Paths.get(...)` | `Path.of(...)` `Java 11` |
| Manual read loops for whole files | `Files.readString` / `readAllBytes` |

---

## Recap

| Concept | One line |
|---|---|
| `Path` | Just a name. `resolve` to join, `normalize`, `relativize` |
| `Files` | `readString`, `writeString`, `copy`, `move`, `createDirectories` — UTF-8 by default |
| ⚠️ `Files.lines`/`walk`/`list`/`find` | **Must be closed** |
| Walking | `walk`, `find`, or `walkFileTree` + visitor |
| **Safe write** | Temp file **in the same directory** → `ATOMIC_MOVE` |
| **Resources** | Bundled files use `getResourceAsStream`, **never `Path`** |
| 💀 `java.io.File` | Boolean failures, no reason. Replaced comprehensively |
