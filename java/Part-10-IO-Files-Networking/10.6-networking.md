## Sockets — write a trivial TCP server once, by hand

Do this once. It makes every HTTP framework stop being magic.

```java
// server
try (var server = new ServerSocket(8080)) {
    while (true) {
        Socket socket = server.accept();                 // BLOCKS until a client connects
        try (socket;
             var in  = new BufferedReader(new InputStreamReader(socket.getInputStream(), UTF_8));
             var out = new PrintWriter(socket.getOutputStream(), true, UTF_8)) {
            String line = in.readLine();
            out.println("echo: " + line);
        }
    }
}
```

```java
// client
try (var socket = new Socket("localhost", 8080);
     var out = new PrintWriter(socket.getOutputStream(), true, UTF_8);
     var in  = new BufferedReader(new InputStreamReader(socket.getInputStream(), UTF_8))) {
    out.println("hello");
    IO.println(in.readLine());
}
```

> **That's the whole model:** a socket is a bidirectional byte stream (10.1). HTTP is just
> an agreed text format on top of it. Note the explicit charsets (10.2) — a socket carries
> bytes, not characters.

**To handle many clients** — one thread per connection, which is viable again with virtual
threads (9.11, 10.4):

```java
try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
    while (true) {
        var socket = server.accept();
        exec.submit(() -> handle(socket));
    }
}
```

**UDP** — connectionless, unreliable, no ordering:

```java
try (var socket = new DatagramSocket(9999)) {
    var buf = new byte[1024];
    var packet = new DatagramPacket(buf, buf.length);
    socket.receive(packet);
}
```

## ⭐ `URI` versus `URL` — and the DNS trap

```java
URI uri = URI.create("https://example.com/path?q=1");     // ✅ use this
URL url = new URL("https://example.com/path");            // ⚠️ legacy
```

> ⭐ **`URL.equals()` and `URL.hashCode()` perform a DNS lookup.**

```java
new URL("http://example.com").equals(new URL("http://93.184.216.34"));
// → may be TRUE, after a blocking network call
```

**The consequences are genuinely bad:**

| | |
|---|---|
| **`equals` blocks on the network** | Unpredictable latency inside a method nobody expects to do I/O |
| **`hashCode` blocks too** | So putting a `URL` in a `HashSet` or `HashMap` does DNS (5.3) |
| **It's not a pure function** | The result changes when DNS changes — violating the `equals` contract (2.5) |
| **It can fail** | No network → different results |

> **Never put a `URL` in a `HashMap` or `HashSet`. Never compare them with `equals`.**
> This is one of the most cited API design mistakes in the JDK.

**`URI` is purely syntactic** — parsing and comparison only, no network, no protocol
handler. Use `URI` everywhere and convert at the last moment if a legacy API needs a `URL`:

```java
URL url = uri.toURL();
```

`URI` also does the parsing you want:

```java
var uri = URI.create("https://user@example.com:8443/a/b?x=1#frag");
uri.getScheme();    // https
uri.getHost();      // example.com
uri.getPort();      // 8443
uri.getPath();      // /a/b
uri.getQuery();     // x=1
uri.resolve("../c"); // relative resolution
```

## ⭐ `HttpClient` — the modern built-in client `Java 11`

Before Java 11 the built-in option was `HttpURLConnection` — a 1997 API so awkward that
everyone used Apache HttpClient or OkHttp instead. `HttpClient` fixed that.

```java
var client = HttpClient.newBuilder()
    .version(HttpClient.Version.HTTP_2)              // default
    .connectTimeout(Duration.ofSeconds(10))
    .followRedirects(HttpClient.Redirect.NORMAL)
    .build();

var request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Accept", "application/json")
    .timeout(Duration.ofSeconds(30))                 // per-request
    .GET()
    .build();
```

**Synchronous:**

```java
HttpResponse<String> response = client.send(request, BodyHandlers.ofString());
response.statusCode();
response.body();
response.headers().firstValue("Content-Type");
```

**Asynchronous** (9.9):

```java
client.sendAsync(request, BodyHandlers.ofString())
      .thenApply(HttpResponse::body)
      .thenAccept(IO::println);
```

> ⭐ **On Java 21+, prefer the synchronous `send()` on a virtual thread** (9.11) over
> `sendAsync`. You get real stack traces, working try/catch (4.3), and simpler code — for
> the same concurrency. Use `sendAsync` for genuine fan-out.

**Request bodies:**

```java
.POST(BodyPublishers.ofString(json))
.POST(BodyPublishers.ofFile(path))
.PUT(BodyPublishers.ofByteArray(bytes))
.DELETE()
.method("PATCH", BodyPublishers.ofString(body))
```

**Response body handlers** — where the response goes:

```java
BodyHandlers.ofString()                 // → String
BodyHandlers.ofByteArray()              // → byte[]
BodyHandlers.ofFile(path)               // ⭐ straight to disk, never fully in memory
BodyHandlers.ofLines()                  // → Stream<String> (6.4) — streaming
BodyHandlers.ofInputStream()            // → InputStream (10.1)
BodyHandlers.discarding()               // throw it away
```

> ⚠️ **`ofString()` buffers the whole body in memory.** For large downloads use `ofFile`
> or `ofInputStream`.

**Connection reuse is automatic** — the client keeps a connection pool and HTTP/2
multiplexes many requests over one connection. **Create one `HttpClient` and reuse it**;
building one per request throws away the pool.

`Java 26` adds **HTTP/3** (QUIC) support.

## The built-in file web server `Java 18`

```bash
jwebserver -p 8000 -d /path/to/files
```

```java
var server = SimpleFileServer.createFileServer(
    new InetSocketAddress(8000), Path.of("/files"), OutputLevel.INFO);
server.start();
```

> **For local testing and demos only** — no HTTPS, no auth, no configuration. It exists so
> you stop reaching for `python -m http.server`.

## TLS basics

```
keystore   = MY identity      (my private key + certificate — what a SERVER presents)
truststore = who I TRUST      (CA certificates — used to VALIDATE the other side)
```

```bash
-Djavax.net.ssl.keyStore=/path/keystore.p12
-Djavax.net.ssl.keyStorePassword=...
-Djavax.net.ssl.trustStore=/path/truststore.p12
```

The JDK ships a default truststore (`$JAVA_HOME/lib/security/cacerts`) containing the
public CAs — which is why HTTPS to a public site works with no configuration.

**Certificate validation** checks: signed by a trusted CA, not expired, hostname matches,
not revoked.

```java
// 💀 NEVER — disabling validation makes TLS pointless
var ctx = SSLContext.getInstance("TLS");
ctx.init(null, new TrustManager[]{ /* trust-everything */ }, null);
```

> ⚠️ **You will find this snippet on Stack Overflow** as a fix for
> `SSLHandshakeException`. It "works" by removing the entire security guarantee — it makes
> you vulnerable to any man-in-the-middle. The real fix is to **add your CA to the
> truststore**:
> ```bash
> keytool -importcert -alias mycompany -file ca.crt -keystore truststore.p12
> ```

`Java 27` negotiates **post-quantum key exchange (ML-KEM)** by default — protecting against
"harvest now, decrypt later" attacks, transparently, with no code change.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `URL` in a `HashMap`/`HashSet` | **`hashCode` does a DNS lookup** |
| `URL.equals` | Blocking, impure, contract-violating |
| A new `HttpClient` per request | Throws away the connection pool |
| `BodyHandlers.ofString()` for large responses | Buffers it all in memory |
| No timeouts | A hung connection blocks forever. Set **both** connect and request timeouts |
| Disabling certificate validation | Removes the entire point of TLS |
| No charset on socket streams | Platform-dependent (10.2) |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `HttpURLConnection` | `HttpClient` `Java 11` |
| `URL` for parsing or comparison | `URI` |
| Trust-everything `TrustManager` | Add the CA to the truststore |
| `Socket` per connection with platform threads | Virtual threads (9.11) |

## Recap

| Concept | One line |
|---|---|
| Socket | A bidirectional **byte** stream. Write one server by hand, once |
| ⭐ `URI` vs `URL` | **`URL.equals`/`hashCode` do DNS.** Use `URI` |
| **`HttpClient`** | `Java 11`. HTTP/2 default, sync + async, **reuse one instance** |
| Body handlers | `ofString` buffers; `ofFile`/`ofInputStream` stream |
| On Java 21+ | Prefer **sync `send()` on a virtual thread** over `sendAsync` |
| `jwebserver` | `Java 18`. Local testing only |
| TLS | **keystore = my identity, truststore = who I trust.** Never disable validation |
