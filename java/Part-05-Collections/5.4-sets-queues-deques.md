# 5.4 — Sets, queues and deques

> **What this is:** Smaller surface than lists and maps, and **each one exists for a
> specific access pattern**. Pick by the pattern, not by familiarity.

---

## Coming from JS/Python/Dart

- `Set` — same as JS `Set` / Python `set`.
- `Deque` — no equivalent you've used. Python's `collections.deque` is the match.
- **`ArrayDeque` is the thing to remember from this page**: it's the correct stack *and*
  the correct queue in Java, and it replaces the two classes people reach for by habit.

---

## Sets

### `HashSet` is a `HashMap` with dummy values

Literally:

```java
// java.util.HashSet — real code
private transient HashMap<E,Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}
```

> **Everything from 5.3 applies unchanged** — buckets, `hashCode`/`equals`, load factor,
> treeification, null handling, the mutated-key trap. A `Set` is a `Map` with the values
> thrown away.

### The three implementations

| | Order | Cost | Use when |
|---|---|---|---|
| `HashSet` | **None guaranteed** | O(1) | Default |
| `LinkedHashSet` | **Insertion** | O(1), slightly more memory | Order matters |
| `TreeSet` | **Sorted** | O(log n) | Need sorted / range queries |

```java
Set<String> a = new HashSet<>(List.of("c","a","b"));        // [a, b, c] — but don't rely on it
Set<String> b = new LinkedHashSet<>(List.of("c","a","b"));  // [c, a, b] — guaranteed
Set<String> c = new TreeSet<>(List.of("c","a","b"));        // [a, b, c] — guaranteed
```

> ⚠️ `HashSet` of small integers often *appears* sorted, because `Integer.hashCode()`
> returns the value itself and small values land in ascending buckets. **This is a
> coincidence** — it breaks as soon as the set resizes or holds larger values. Never rely
> on it.

`TreeSet` implements `NavigableSet` — the `floor`/`ceiling`/`headSet`/`tailSet` family
from 5.3.

### Set algebra

```java
Set<String> a = new HashSet<>(Set.of("1","2","3"));
Set<String> b = Set.of("2","3","4");

a.addAll(b);       // UNION        → {1,2,3,4}
a.retainAll(b);    // INTERSECTION → {2,3}
a.removeAll(b);    // DIFFERENCE   → {1}
a.containsAll(b);  // SUBSET test
```

> ⚠️ These **mutate `a` in place** and return `boolean` (did anything change?), not a new
> set. For a non-destructive version, copy first:
> ```java
> var union = new HashSet<>(a); union.addAll(b);
> ```

**Performance note:** `removeAll` has a nasty asymmetry. If `a` is much bigger than `b`,
it iterates `b`; otherwise it iterates `a` and calls `b.contains()`. If `b` is a `List`,
that's O(n×m). **Make sure the argument is a `Set`.**

## Queues and Deques

### The two method families

This is the part worth memorising. **Every queue operation has two versions** — one that
throws, one that returns a sentinel value:

| Operation | Throws on failure | Returns sentinel |
|---|---|---|
| Insert | `add(e)` → `IllegalStateException` | `offer(e)` → `false` |
| Remove | `remove()` → `NoSuchElementException` | `poll()` → `null` |
| Examine | `element()` → `NoSuchElementException` | `peek()` → `null` |

```java
Queue<String> q = new ArrayDeque<>();
q.offer("a");
q.poll();       // "a"
q.poll();       // null — empty, no exception
q.remove();     // 💥 NoSuchElementException
```

**When to use which:**

- **`offer`/`poll`/`peek`** — when empty or full is a **normal** condition. This is the
  common case.
- **`add`/`remove`/`element`** — when empty means a **bug**, and you want to fail loudly
  (4.4).

> Same reasoning as 4.2: is this outcome exceptional, or one of the normal results?

### `Deque` — both ends

```java
Deque<String> d = new ArrayDeque<>();

d.addFirst("a");   d.offerFirst("a");
d.addLast("b");    d.offerLast("b");
d.pollFirst();     d.pollLast();
d.peekFirst();     d.peekLast();
```

Plus stack-style aliases:

```java
d.push(x);    // = addFirst
d.pop();      // = removeFirst
d.peek();     // = peekFirst
```

## ⭐ `ArrayDeque` — the correct stack *and* the correct queue

```java
// ✅ as a STACK (LIFO)
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2); stack.push(3);
stack.pop();                      // 3
for (int i : stack) IO.println(i); // 2, 1 — top first ✅

// ✅ as a QUEUE (FIFO)
Queue<Integer> queue = new ArrayDeque<>();
queue.offer(1); queue.offer(2);
queue.poll();                     // 1
```

**Use it instead of `Stack` and `LinkedList`:**

| Instead of | Use | Why |
|---|---|---|
| 💀 `Stack` | `ArrayDeque` | `Stack` extends `Vector` (synchronised, 5.1) and **iterates bottom-to-top** |
| 💀 `LinkedList` as a queue | `ArrayDeque` | Circular array — contiguous memory, no per-node objects (5.2) |

`ArrayDeque` is a **circular array** with head and tail indices. Adding/removing at either
end is O(1) with no allocation, and the elements are contiguous, so iteration is
cache-friendly.

> ⚠️ `ArrayDeque` **does not permit `null`** — because `poll()`/`peek()` use `null` as the
> "empty" sentinel. Storing a null would make the result ambiguous.

### `PriorityQueue` — a binary heap

```java
Queue<Integer> pq = new PriorityQueue<>();
pq.offer(5); pq.offer(1); pq.offer(3);

pq.poll();      // 1  — always the SMALLEST
pq.poll();      // 3
pq.poll();      // 5
```

With a comparator (5.5):
```java
new PriorityQueue<>(Comparator.reverseOrder());          // max-heap
new PriorityQueue<>(Comparator.comparing(Task::priority));
```

**⚠️ The trap: iteration order is NOT sorted order.**

```java
var pq = new PriorityQueue<>(List.of(5, 1, 3, 2, 4));

for (int i : pq) IO.print(i + " ");     // 1 2 3 5 4   ← heap array order, NOT sorted
IO.println(pq);                          // [1, 2, 3, 5, 4]  ← same
```

Only `poll()` gives sorted order. The backing array is a **binary heap** — it guarantees
only that each parent is ≤ its children, not a total ordering.

```
heap array:  [1, 2, 3, 5, 4]

as a tree:        1
                /   \
               2     3
              / \
             5   4        ← parent ≤ children everywhere. Not sorted.
```

**To get sorted output**, drain it:
```java
while (!pq.isEmpty()) IO.println(pq.poll());
```

| Operation | Cost |
|---|---|
| `offer` | O(log n) |
| `poll` | O(log n) |
| `peek` | **O(1)** |
| `contains` / `remove(Object)` | O(n) — linear scan |

### `BlockingQueue` — noted here, used in Part 09

```java
BlockingQueue<Task> q = new LinkedBlockingQueue<>();
q.put(task);           // BLOCKS if full
Task t = q.take();     // BLOCKS if empty
```

The producer/consumer primitive. Adds a **third** method family — `put`/`take`, which
block rather than throwing or returning null. Full treatment in 9.7.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `HashSet` of ints appears sorted | Coincidence of `Integer.hashCode()`. Breaks on resize |
| `PriorityQueue` iterates in order | **No** — heap order. Only `poll()` is sorted |
| `Stack` for a stack | Iterates backwards, extends `Vector`. Use `ArrayDeque` |
| `null` into `ArrayDeque` | NPE — null is the empty sentinel |
| `a.removeAll(listArgument)` | O(n×m). Pass a `Set` |
| `addAll`/`retainAll` return a new set | They mutate in place and return `boolean` |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `Stack` | `ArrayDeque` (as a stack) |
| `LinkedList` as a queue/deque | `ArrayDeque` |
| `Vector` | `ArrayList` |

## Recap

| Type | Key fact |
|---|---|
| `HashSet` | A `HashMap` with dummy values. All of 5.3 applies |
| `LinkedHashSet` / `TreeSet` | Insertion order / sorted |
| Set algebra | `addAll`/`retainAll`/`removeAll` = union/intersection/difference, **in place** |
| Two method families | `add`/`remove`/`element` throw; `offer`/`poll`/`peek` return a sentinel |
| **`ArrayDeque`** | The correct stack **and** queue. No nulls |
| `PriorityQueue` | Binary heap. `peek` O(1), `poll` O(log n), **iteration ≠ sorted** |
| `BlockingQueue` | A third family (`put`/`take`) that blocks — Part 09 |
