# 11.7 — Annotations

> **What this is:** The other half of the framework mechanism. ⭐ **Annotations do nothing
> until something reads them.**

---

## ⭐ The one idea

```java
@Transactional
public void transfer(...) { ... }
```

**This annotation does not start a transaction.** It does nothing at all. It is a **label**
attached to the method, and somewhere else a piece of code reads that label via reflection
(11.6) and wraps the method in a proxy that starts a transaction.

> **An annotation is data, not behaviour.** Every "magic" annotation you'll meet in Spring,
> JPA, JUnit or Jackson is inert metadata plus a reader somewhere. Once you've written the
> reader yourself (below), the magic is gone permanently.

---

## Declaring one

```java
@Retention(RetentionPolicy.RUNTIME)      // ⭐ must be RUNTIME to be readable
@Target(ElementType.METHOD)
public @interface Timed {
    String value() default "";            // elements look like methods
    boolean logResult() default false;
    String[] tags() default {};           // arrays allowed
}
```

```java
@Timed("payment")                         // `value` can be unnamed if it's the only one set
@Timed(value = "payment", logResult = true, tags = {"api", "critical"})
```

**Element types are restricted:** primitives, `String`, `Class`, enums, other annotations,
and arrays of those. **No arbitrary objects, and no `null`** — use a sentinel default.

---

## ⭐ `@Retention` — the one that actually matters

```java
RetentionPolicy.SOURCE     // discarded by javac — not in the .class file
RetentionPolicy.CLASS      // in the .class file, NOT loaded at runtime (the default)
RetentionPolicy.RUNTIME    // ⭐ in the .class file AND readable by reflection
```

| Policy | Visible to | Example |
|---|---|---|
| `SOURCE` | The compiler and annotation processors only | `@Override`, `@SuppressWarnings`, Lombok |
| `CLASS` | Bytecode tools | Nullability annotations for static analysis |
| **`RUNTIME`** | **Reflection** (11.6) | `@Transactional`, `@Test`, `@Entity`, `@JsonProperty` |

> ⭐ **If your annotation isn't `RUNTIME`, `getAnnotation()` returns `null`** and your
> framework silently does nothing. **This is the most common mistake when writing your
> first annotation**, and it fails with no error message.

## `@Target`, `@Inherited`, `@Repeatable`

```java
@Target({ElementType.METHOD, ElementType.TYPE})
// TYPE, FIELD, METHOD, PARAMETER, CONSTRUCTOR, LOCAL_VARIABLE,
// ANNOTATION_TYPE, PACKAGE, TYPE_PARAMETER, TYPE_USE, RECORD_COMPONENT
```

```java
@Inherited          // ⚠️ subclasses inherit it — CLASSES ONLY, not methods or interfaces
```

```java
@Repeatable(Schedules.class)         // apply it more than once
public @interface Schedule { String cron(); }

@Schedule(cron = "0 0 * * *")
@Schedule(cron = "0 12 * * *")
void job() { }
```

**Meta-annotations** — annotations on annotations. This is how Spring composes:

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Controller                          // ⭐ meta-annotated
@ResponseBody                        // ⭐ meta-annotated
public @interface RestController { }
```

`@RestController` *is* `@Controller` + `@ResponseBody`. Spring resolves meta-annotations
transitively, which is why one annotation can carry a stack of behaviour.

---

## The built-in ones

```java
@Override                    // SOURCE — catches typos and signature drift (2.3)
@FunctionalInterface         // SOURCE — rejects a second abstract method (2.4)
@SafeVarargs                 // SOURCE — suppresses heap pollution warnings (3.5)
@SuppressWarnings("unchecked")  // SOURCE — narrowest scope + a reason (3.3)

@Deprecated(since = "2.5", forRemoval = true)     // ⭐ Java 9 added both elements
```

> ⭐ **`forRemoval = true` upgrades the warning to a strong one** and tells `jdeprscan`
> (12.1) to flag it. `since` tells a reader how long they've had. Both are worth setting —
> a bare `@Deprecated` gives the reader nothing to act on.

## ⭐ Reading them — write a tiny framework

**Do this once.** It makes every framework concrete.

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Test { }

class MiniJUnit {
    static void run(Class<?> testClass) throws Exception {
        Object instance = testClass.getDeclaredConstructor().newInstance();   // (11.6)

        for (Method m : testClass.getDeclaredMethods()) {
            if (!m.isAnnotationPresent(Test.class)) continue;    // ⭐ read the label

            try {
                m.invoke(instance);
                IO.println("✅ " + m.getName());
            } catch (InvocationTargetException e) {
                IO.println("❌ " + m.getName() + ": " + e.getCause());   // unwrap (4.3)
            }
        }
    }
}
```

**That is JUnit.** Find methods carrying a label, call them, report. Everything else —
lifecycle hooks, parameterised tests, assertions, extensions (12.3) — is elaboration on
those six lines.

```java
// reading elements
var timed = method.getAnnotation(Timed.class);
if (timed != null) {
    String name = timed.value();
    boolean log = timed.logResult();
}

method.getAnnotations();
method.isAnnotationPresent(Timed.class);
method.getAnnotationsByType(Schedule.class);      // for @Repeatable
```

> ⭐ **Combine this with 11.6's dynamic proxy and you have Spring's core**: read the
> annotations, decide what behaviour to add, wrap the bean in a proxy that adds it.

## ⭐ Annotation processors — code generation at compile time

A **different mechanism entirely**: processors run **during compilation** and can
**generate new source files**.

```
javac → discovers processors on the classpath → each sees the annotated elements
      → processors generate .java files → those are compiled too → repeat until stable
```

```java
public class MyProcessor extends AbstractProcessor {
    @Override public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment env) {
        for (Element e : env.getElementsAnnotatedWith(Builder.class)) {
            generateBuilderClass(e);          // write a .java file
        }
        return true;
    }
}
```

**How the tools you know work:**

| Tool | Does |
|---|---|
| **Lombok** | ⚠️ **Mutates the AST** — technically an abuse of the API, not code generation. Powerful and fragile; breaks on JDK upgrades |
| **MapStruct** | Generates real mapper **source** — readable, debuggable, zero runtime cost |
| **Immutables / AutoValue** | Generate immutable value classes — largely **obsoleted by records** (2.6) |
| **Dagger** | Generates DI wiring at **compile time** — no runtime reflection, so it works in native images (8.10) |

> ⭐ **Compile-time generation beats runtime reflection** where it's possible: no startup
> cost, no reflection config for native images, and the generated code is debuggable.
> That's why Quarkus and Micronaut do at build time what Spring historically did at
> startup.

```xml
<!-- annotation processors go in this Maven scope -->
<annotationProcessorPaths>...</annotationProcessorPaths>
```

## Type annotations `Java 8`

`ElementType.TYPE_USE` lets annotations appear anywhere a **type** appears:

```java
@NonNull String name;
List<@NonNull String> names;
String str = (@NonNull String) obj;
void f() throws @Critical IOException { }
```

**Enables pluggable type systems** — a checker runs as an annotation processor and enforces
rules the language doesn't:

| Tool | Checks |
|---|---|
| **Checker Framework** | Null safety, tainting, units, immutability |
| **NullAway** | Null safety, fast enough for every build |
| **JSpecify** | A standard set of nullability annotations (12.5) |

```java
// with NullAway on, this is a BUILD ERROR
@Nullable String name;
name.length();          // ❌ dereference of a @Nullable value
```

> **This is the closest Java gets to Kotlin's null safety** — opt-in, tool-enforced, and
> genuinely effective on a codebase that adopts it consistently. `@Nullable` alone does
> nothing (see the one idea at the top); the **checker** is what enforces it.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| **Forgetting `@Retention(RUNTIME)`** | `getAnnotation()` returns `null`, silently |
| Expecting an annotation to *do* something | It's inert until something reads it |
| `@Inherited` on a method | **Classes only** |
| `null` as an element value | Not allowed. Use a sentinel default |
| Bare `@Deprecated` | Add `since` and `forRemoval` |
| Lombok on a new JDK | It hooks compiler internals; upgrades break it |
| Annotations on a private method expecting a proxy | Proxies can't intercept private or self-calls (11.6) |

---

## Recap

| Concept | One line |
|---|---|
| ⭐ **The one idea** | **Annotations are inert data.** Something must read them |
| ⭐ **`@Retention`** | **`RUNTIME`** or reflection can't see it |
| `@Target` | Where it may be applied |
| `@Inherited` | Classes only |
| Meta-annotations | `@RestController` = `@Controller` + `@ResponseBody` |
| `@Deprecated(since, forRemoval)` | `Java 9`. Set both |
| Reading them | `isAnnotationPresent` + `getAnnotation` — **that's JUnit** |
| Processors | **Compile-time generation.** MapStruct, Dagger. Beats runtime reflection |
| `TYPE_USE` | Pluggable type systems — NullAway, Checker Framework |
