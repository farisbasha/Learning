# 11.9 — Foreign functions and memory

> **What this is:** Calling native code, **finally without writing C**. A genuinely modern
> replacement for a thirty-year-old API. `Java 22`

---

## 💀 JNI — why it was painful

```java
public class Legacy {
    static { System.loadLibrary("mylib"); }
    public native int compute(int x);          // implemented in C
}
```

```c
/* and you had to hand-write this, in C */
JNIEXPORT jint JNICALL Java_Legacy_compute(JNIEnv *env, jobject obj, jint x) {
    return x * 2;
}
```

| Problem | |
|---|---|
| **Hand-written C glue** | Every function needed a C wrapper with a mangled name |
| **A separate toolchain** | A C compiler, per platform, in your build |
| **No safety** | A mistake **crashes the JVM** — no exception, just a core dump |
| **Manual memory management** | Leaks and use-after-free, in a garbage-collected language |
| **Slow transitions** | The JNI boundary blocked JIT optimisation (8.8) |
| **Brittle** | `GetStringUTFChars` without a matching `Release` leaks, silently |

> JNI is from 1997 and it shows. It's the reason "just call the C library" was a
> multi-week task in Java and a one-liner in Python.

---

## ⭐ The Foreign Function & Memory API `Java 22`

**Calling C from pure Java. No C code, no separate toolchain.**

```java
import java.lang.foreign.*;
import static java.lang.foreign.ValueLayout.*;

// call strlen("hello") from libc
try (var arena = Arena.ofConfined()) {
    Linker linker = Linker.nativeLinker();
    SymbolLookup stdlib = linker.defaultLookup();

    MethodHandle strlen = linker.downcallHandle(          // (11.8)
        stdlib.find("strlen").orElseThrow(),
        FunctionDescriptor.of(JAVA_LONG, ADDRESS));       // returns long, takes a pointer

    MemorySegment str = arena.allocateFrom("hello");      // off-heap C string
    long len = (long) strlen.invokeExact(str);            // 5
}
```

**That's the whole thing.** No C, no `javah`, no platform-specific build step.

## ⭐ `Arena` — deterministic lifetimes for off-heap memory

**This is the part that fixes JNI's worst property.**

```java
try (var arena = Arena.ofConfined()) {          // ⭐ try-with-resources (4.3)
    MemorySegment seg = arena.allocate(1024);
    ...
}   // ⭐ ALL memory allocated from this arena is freed HERE, deterministically
```

| Arena | Lifetime | Threads |
|---|---|---|
| **`ofConfined()`** | Until `close()` | ⭐ **One thread only** — enforced |
| `ofShared()` | Until `close()` | Any thread (slower close) |
| `ofAuto()` | **GC decides** | Any |
| `global()` | The JVM's lifetime | Any |

> ⭐ **`ofConfined()` is the default choice.** Deterministic free, and the JVM **enforces**
> single-thread access — touching the segment from another thread throws rather than
> corrupting memory (9.2).

**Unlike a direct `ByteBuffer`** (10.4), whose memory is freed nondeterministically by a
`Cleaner` (8.7), an arena frees **exactly when the block exits**. That's a genuine
improvement for large off-heap buffers.

## ⭐ `MemorySegment` and `MemoryLayout` — safety JNI never had

```java
MemorySegment seg = arena.allocate(100);

seg.set(JAVA_INT, 0, 42);            // write at offset 0
int v = seg.get(JAVA_INT, 0);

seg.set(JAVA_INT, 200, 1);           // 💥 IndexOutOfBoundsException — SPATIAL safety
```

```java
var seg = arena.allocate(100);
arena.close();
seg.get(JAVA_INT, 0);                // 💥 IllegalStateException — TEMPORAL safety
```

| Safety | Means |
|---|---|
| ⭐ **Spatial** | **Bounds-checked.** You cannot read past the end |
| ⭐ **Temporal** | **Use-after-free is caught.** Accessing a closed arena throws |

> **JNI had neither.** A mistake in JNI corrupts memory or crashes the JVM; the same
> mistake here throws an ordinary Java exception you can catch (4.1).

**`MemoryLayout`** describes a C struct declaratively:

```java
// struct Point { int x; int y; };
StructLayout POINT = MemoryLayout.structLayout(
    JAVA_INT.withName("x"),
    JAVA_INT.withName("y"));

var xHandle = POINT.varHandle(PathElement.groupElement("x"));   // a VarHandle (9.6, 11.8)

var p = arena.allocate(POINT);
xHandle.set(p, 0L, 10);
int x = (int) xHandle.get(p, 0L);
```

Layouts handle alignment and padding (8.4) for you — no manual offset arithmetic.

## `Linker`, downcalls and upcalls

**Downcall** — Java → native (the common direction):

```java
MethodHandle qsort = linker.downcallHandle(
    stdlib.find("qsort").orElseThrow(),
    FunctionDescriptor.ofVoid(ADDRESS, JAVA_LONG, JAVA_LONG, ADDRESS));
```

**Upcall** — native → Java (a C callback implemented in Java):

```java
// a Java method the C code will call back into
static int compare(MemorySegment a, MemorySegment b) {
    return Integer.compare(a.get(JAVA_INT, 0), b.get(JAVA_INT, 0));
}

MethodHandle cmp = MethodHandles.lookup()                      // (11.8)
    .findStatic(Main.class, "compare",
        MethodType.methodType(int.class, MemorySegment.class, MemorySegment.class));

MemorySegment cmpPtr = linker.upcallStub(cmp, descriptor, arena);
qsort.invoke(array, count, 4L, cmpPtr);        // C calls back into Java
```

> A C function pointer, implemented in Java, with no C written. That was essentially
> impossible with JNI without a C shim.

## `jextract` — generating bindings from C headers

Writing descriptors by hand for a large library is tedious. `jextract` does it:

```bash
jextract --output src/gen -t org.example.sqlite \
         -I /usr/include /usr/include/sqlite3.h
```

Generates Java bindings for every function, struct and constant in the header.

```java
import static org.example.sqlite.sqlite3_h.*;

try (var arena = Arena.ofConfined()) {
    var db = arena.allocate(ADDRESS);
    sqlite3_open(arena.allocateFrom("test.db"), db);
}
```

> `jextract` ships separately from the JDK. It's the practical entry point for wrapping a
> real library.

---

## ⚠️ It's still native code

```bash
java --enable-native-access=ALL-UNNAMED ...      # required; warns without it
```

FFM is **restricted** — a native call can still crash the JVM if you pass a bad pointer or
describe a signature wrongly. The safety guarantees cover **memory segments you allocate**;
they cannot cover what the C code does with what you hand it.

> Java 24+ warns on unrestricted native access, and future versions will require the flag.
> The same applies to JNI.

## Where this matters

| Use | Why |
|---|---|
| **Native libraries** | SQLite, OpenSSL, CUDA, TensorFlow, platform APIs |
| **Off-heap data** | Large datasets outside the heap → **no GC pressure** (8.5) |
| **Memory-mapped structures** | Reading a binary format as a struct (10.4) |
| **Avoiding GC pressure** | Multi-GB caches the collector never has to scan |
| Zero-copy interop | Sharing buffers with native code without copying |

> ⭐ **The off-heap case is underrated.** A 10 GB in-memory index in a `HashMap` is 10 GB
> the GC must traverse (8.5). The same data in a `MemorySegment` is invisible to the
> collector — no scanning, no pauses from it.

Real adopters: **Netty** (replacing `Unsafe`), **Apache Arrow**, **Lucene** (replacing
`MappedByteBuffer`), and every JVM database that touches native storage.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| Not using try-with-resources on an `Arena` | Leaks off-heap memory |
| Using a segment after `arena.close()` | Throws — **temporal safety**, but still a bug |
| `ofConfined` across threads | Throws. Use `ofShared` if you genuinely need it |
| A wrong `FunctionDescriptor` | **Undefined behaviour** — can crash the JVM |
| Expecting full safety | Bounds and lifetime are checked; **the C code is not** |
| Forgetting `--enable-native-access` | Warnings now, an error later |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| **JNI** in new code | **FFM API** `Java 22` |
| `sun.misc.Unsafe` for off-heap memory | `MemorySegment` / `Arena` |
| `ByteBuffer.allocateDirect` for large lifetimes | `Arena` — deterministic free (10.4) |

## Recap

| Concept | One line |
|---|---|
| 💀 JNI | Hand-written C glue, no safety, crashes the JVM |
| **FFM** `Java 22` | Call C **from pure Java**. No C, no extra toolchain |
| ⭐ **`Arena`** | **Deterministic** free via try-with-resources. `ofConfined` is the default |
| ⭐ **`MemorySegment`** | **Spatial + temporal safety** — bounds-checked, use-after-free throws |
| `MemoryLayout` | Describe C structs; alignment handled for you |
| Downcall / upcall | Java→native / native→Java callbacks |
| `jextract` | Generate bindings from a C header |
| Why it matters | Native libraries, **off-heap data with no GC pressure** |
