# 11.6 — Reflection

> **What this is:** **The mechanism behind every framework you will ever use in Java.**
> Understanding it removes the magic permanently.

---

## `Class` objects — the three ways to get one

```java
Class<String> c1 = String.class;                    // 1. class literal — compile time
Class<?>      c2 = someObject.getClass();           // 2. from an instance (2.5)
Class<?>      c3 = Class.forName("java.lang.String"); // 3. by name — RUNTIME lookup
```

The third is the interesting one: **a `String` becomes executable code**. That's the
foundation of every plugin system, DI container and ORM.

```java
Class.forName("com.example.Plugin", false, loader);   // don't initialise (8.2)
```

---

## Inspecting

```java
c.getName();               // com.example.User
c.getSimpleName();         // User
c.getSuperclass();
c.getInterfaces();
c.getModifiers();          // Modifier.isPublic(...), isStatic(...), isFinal(...)

c.getFields();             // public fields, INCLUDING inherited
c.getDeclaredFields();     // ⭐ ALL fields declared HERE, including private
c.getDeclaredMethods();
c.getDeclaredConstructors();
c.getAnnotations();        // (11.7)
c.isRecord();  c.getRecordComponents();     // Java 16 (2.6)
c.isSealed();  c.getPermittedSubclasses();  // Java 17 (2.8)
```

> ⭐ **`getX()` vs `getDeclaredX()`:** `getFields()` returns **public** members including
> inherited ones; `getDeclaredFields()` returns **all** members (private included) declared
> **on this class only**. To get everything, walk the superclass chain yourself.

**Generic signatures survive** (3.3) — erasure removes type arguments from the *bytecode*,
but the `Signature` attribute (8.1) is readable:

```java
Field f = c.getDeclaredField("names");       // List<String> names
f.getType();                                  // interface java.util.List  ← erased
f.getGenericType();                           // java.util.List<java.lang.String>  ⭐
```

> **This is how Jackson deserialises `List<User>` correctly** — it reads the generic
> signature of the field or the constructor parameter. It's the same information the
> super type token trick (3.5) recovers when there's no field to read.

## Invoking

```java
// create an instance
var ctor = User.class.getDeclaredConstructor(String.class, int.class);
User u = ctor.newInstance("Basha", 30);

// call a method
var m = User.class.getDeclaredMethod("greet", String.class);
Object result = m.invoke(u, "hello");

// read and write a field
var f = User.class.getDeclaredField("name");
f.setAccessible(true);                       // ⚠️ see below
f.set(u, "New Name");                        // ⭐ writes a PRIVATE field
Object v = f.get(u);
```

💀 `c.newInstance()` is deprecated — it swallows checked exceptions. Use
`getDeclaredConstructor().newInstance()`.

> ⚠️ **Exceptions from `invoke` are wrapped** in `InvocationTargetException`. Unwrap with
> `getCause()` (4.3) or you'll log a useless wrapper.

---

## ⭐ `setAccessible` — breaking encapsulation

```java
field.setAccessible(true);      // ⭐ ignore private/protected
```

**This is how frameworks populate your private fields** without setters — Hibernate,
Jackson, Spring's `@Autowired` on fields all do exactly this.

### The module system's restrictions `Java 9`

Since Java 9, **strong encapsulation** (11.10) limits it:

```
java.lang.reflect.InaccessibleObjectException: Unable to make field private
java.lang.String.value accessible: module java.base does not "opens java.lang" to
unnamed module @...
```

**The escape hatch you will meet in real build files:**

```bash
--add-opens java.base/java.lang=ALL-UNNAMED
--add-opens java.base/java.util=ALL-UNNAMED
```

> If you've ever seen a wall of `--add-opens` flags in a Maven surefire config or a
> `JAVA_OPTS`, **this is what they're for** — a library reflecting into JDK internals that
> were sealed in Java 9 and enforced in Java 16.

### ⭐ Warnings on reflective `final` mutation — blocked in `Java 26`

```java
var f = Integer.class.getDeclaredField("value");
f.setAccessible(true);
f.set(someInteger, 99);          // ⚠️ warns now, FAILS in Java 26
```

Java 25 warns; **Java 26 blocks reflective mutation of `final` fields** entirely.

**Why:** the `final` field guarantee (9.3) — the one that makes immutable objects safe to
share with no synchronisation — is only sound if `final` really means final. The JIT
constant-folds `final` values (8.8); mutating one reflectively makes optimised code
observe a stale value.

> ⚠️ **This will break older libraries.** Anything mutating `final` fields — some
> serialisation frameworks, mocking libraries, older DI containers — needs updating. If you
> maintain a build, expect this on the Java 26 upgrade. `--enable-final-field-mutation` is
> the temporary escape hatch.

## ⭐ Dynamic proxies

**How an interface gets an implementation at runtime.**

```java
interface UserService { User findById(String id); }

var proxy = (UserService) Proxy.newProxyInstance(
    UserService.class.getClassLoader(),
    new Class<?>[]{ UserService.class },
    (p, method, args) -> {                            // InvocationHandler
        IO.println("calling " + method.getName());     // before
        Object result = method.invoke(realImpl, args);
        IO.println("returned " + result);              // after
        return result;
    });

proxy.findById("42");     // prints, delegates, prints
```

**The JVM generates a class at runtime** implementing `UserService`, where every method
routes into your handler.

> ⭐ **This is `@Transactional`, `@Cacheable`, `@Retryable`, Spring Data repositories, and
> every AOP aspect.** Spring wraps your bean in a proxy that starts a transaction, calls
> your method, then commits or rolls back.
>
> **And it explains the classic Spring gotcha:** calling `this.transactionalMethod()` from
> within the same class does **nothing** — you bypassed the proxy. The annotation only
> works on calls that come *through* the proxy from outside.

⚠️ `Proxy` only works for **interfaces**. For classes, frameworks use bytecode generation
(CGLIB, ByteBuddy) to create a subclass — which is why Spring requires non-final classes
and methods for class-based proxies.

---

## ⭐ The cost

| | |
|---|---|
| **No inlining** | The JIT can't inline a reflective call (8.8) — it can't know the target |
| **No compile-time checking** | A renamed method fails at **runtime** |
| **Slower** | Roughly 2–10× a direct call, though much better than it was |
| **Access checks** | Repeated on every call unless `setAccessible(true)` |
| ⭐ **Native images struggle** | Static analysis can't see reflective calls (8.10) |

```java
// ⭐ cache the lookups — most of the cost is finding the member, not calling it
private static final Method METHOD = User.class.getDeclaredMethod("greet", String.class);
```

**`MethodHandle` is the faster alternative** (11.8) — JIT-friendly, because the JVM can
treat a constant handle as a direct call.

> **The native-image point matters** (8.10): everything reflective must be declared in
> `reflect-config.json`, because the closed-world compiler cannot see
> `Class.forName(someString)`. This is the single biggest friction in GraalVM native
> builds, and it's a direct consequence of this page.

## ⭐ Connecting it back — how a DI container works

This is the payoff. Here is Spring, in miniature:

```java
class MiniContainer {
    private final Map<Class<?>, Object> beans = new HashMap<>();

    <T> T create(Class<T> type) throws Exception {
        // 1. find the constructor
        var ctor = type.getDeclaredConstructors()[0];

        // 2. look at what it asks for — ⭐ THIS is constructor injection (2.10, 12.3)
        Object[] args = Arrays.stream(ctor.getParameterTypes())
                              .map(this::getOrCreate)
                              .toArray();

        // 3. build it
        @SuppressWarnings("unchecked")
        T bean = (T) ctor.newInstance(args);

        // 4. wrap it in a proxy if it has annotations that need one (11.7)
        return bean;
    }
}
```

> ⭐ **That's the whole mechanism.** A DI container reads your constructor's parameter
> types by reflection, recursively supplies them, and wraps the result in a dynamic proxy
> when an annotation demands it.
>
> **This is why 2.10 said "inject dependencies through the constructor"** — it's not just
> good design, it's the thing that makes the container able to see what you need.
>
> Spring is ~1 million lines of caching, lifecycle management, scoping and edge cases on
> top of these four steps. But the core really is this.

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `getFields()` to find private fields | Use `getDeclaredFields()` |
| `getDeclaredFields()` to find inherited ones | It's **this class only** — walk the chain |
| Not unwrapping `InvocationTargetException` | You log a useless wrapper |
| Reflection in a hot path without caching | Lookup dominates the cost |
| `setAccessible` on JDK internals | Blocked since Java 16 — needs `--add-opens` |
| Reflectively mutating a `final` field | Warns now, **blocked in Java 26** |
| `this.transactionalMethod()` | Bypasses the proxy. Does nothing |
| Reflection in a GraalVM native image | Needs explicit configuration (8.10) |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `clazz.newInstance()` | `getDeclaredConstructor().newInstance()` |
| Reflection where an interface would do | Just call the method |
| Reflective `final` mutation | Nothing. It's being removed |

## Recap

| Concept | One line |
|---|---|
| `Class` | Three ways: literal, `getClass()`, **`forName`** |
| `getX` vs `getDeclaredX` | Public + inherited vs **all, this class only** |
| `getGenericType()` | Generic info **survives** in the `Signature` attribute (3.3) |
| `setAccessible(true)` | How frameworks fill your private fields. Restricted since Java 9 |
| `--add-opens` | The escape hatch you'll meet in build files |
| **`final` mutation** | Warns now, **blocked `Java 26`** — protects the 9.3 guarantee |
| **Dynamic proxies** | How `@Transactional` works. Interfaces only |
| Cost | No inlining, no compile checks, **breaks native images** |
| ⭐ **DI containers** | Read the constructor's parameter types, supply them, proxy the result |
