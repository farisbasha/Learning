# 11.4 — Text, locale and formatting

> **What this is:** Short, **but it decides whether your software works outside your own
> country.**

---

## ⭐ `Locale` — and why a default locale is a bug

```java
Locale.getDefault();                    // ⚠️ comes from the OS — machine-dependent
Locale.US, Locale.FRANCE, Locale.GERMANY
Locale.of("en", "GB");                  // Java 19 — replaces the deprecated constructor
Locale.forLanguageTag("pt-BR");
```

**Anything that uses the default locale behaves differently on different machines** — your
laptop, the CI runner, the production container, a customer's machine.

### ⭐ The Turkish `toUpperCase()` — the classic example

```java
"i".toUpperCase();                      // ⚠️ depends on the default locale
```

| Locale | Result |
|---|---|
| English | `"I"` |
| **Turkish** (`tr`) | **`"İ"`** — capital I with a dot |

In Turkish, dotted and dotless `i` are **different letters**. So:

```java
// ❌ this breaks on a Turkish-locale machine
if (header.toUpperCase().equals("CONTENT-DISPOSITION")) { ... }
```

**Measured on OpenJDK 17**, uppercasing real HTTP headers in the Turkish locale:

| Header | `toUpperCase(tr)` | Matches? |
|---|---|---|
| `content-type` | `CONTENT-TYPE` | ✅ — **no `i` in it** |
| `if-match` | `İF-MATCH` | ❌ |
| `content-disposition` | `CONTENT-DİSPOSİTİON` | ❌ |
| `accept-encoding` | `ACCEPT-ENCODİNG` | ❌ |

> ⭐ **Note the first row.** The example everyone quotes — `content-type` — happens to
> contain no `i`, so it works. That is exactly why this bug survives code review: it
> breaks on *some* strings and not others, so a quick test passes.

**And `toLowerCase` is equally affected**, via the dotless `ı`:

```java
"TITLE".toLowerCase(turkish);        // "tıtle"  — does NOT equal "title"
```

**This has caused real production outages** — a Java server running in a Turkish locale
failing to recognise HTTP headers, SQL keywords, or config keys.

```java
// ✅ for protocol/identifier comparison — locale-INDEPENDENT
"i".toUpperCase(Locale.ROOT);
s.equalsIgnoreCase(other);              // ✅ also locale-independent

// ✅ for text shown to a user — use THEIR locale
name.toUpperCase(userLocale);
```

> ⭐ **The rule: `Locale.ROOT` for anything machine-facing (protocols, identifiers,
> keys, formats you parse). The user's locale for anything human-facing.** Never the
> default.

Same applies to `toLowerCase`, `String.format`, `NumberFormat`, and sorting.

## Number and currency formatting

```java
NumberFormat.getInstance(Locale.GERMANY).format(1234.56);      // 1.234,56
NumberFormat.getInstance(Locale.US).format(1234.56);           // 1,234.56

NumberFormat.getCurrencyInstance(Locale.UK).format(1234.56);   // £1,234.56
NumberFormat.getCurrencyInstance(Locale.JAPAN).format(1234);   // ￥1,234

NumberFormat.getPercentInstance(Locale.US).format(0.755);      // 76%
```

> ⚠️ **Currency formatting places the symbol differently, uses different separators, and
> different decimal counts** (JPY has none). Never build a currency string by hand —
> `"$" + amount` is wrong for most of the world.

See 11.2 for the parsing side — `1.234,56` means different things in different locales.

## `DateTimeFormatter` localisation

```java
DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG)
    .withLocale(Locale.FRANCE)
    .format(LocalDate.of(2026, 9, 20));        // 20 septembre 2026

DateTimeFormatter.ofPattern("d MMMM yyyy", Locale.GERMAN);   // 20 September 2026
```

> **Prefer `ofLocalizedDate`/`ofLocalizedDateTime` over a hand-written pattern** for
> user-facing dates — different locales order day/month/year differently, and a fixed
> pattern imposes your country's order on everyone. Use an explicit pattern for
> **machine-readable** formats (ISO-8601, 11.1).

## `ResourceBundle` — message properties

```
messages.properties            # the default/fallback
messages_fr.properties
messages_de_DE.properties
```

```properties
# messages.properties
greeting=Hello, {0}!
items.count={0} items
```

```java
var bundle = ResourceBundle.getBundle("messages", Locale.FRANCE);
bundle.getString("greeting");
```

**Lookup falls back progressively:** `messages_fr_FR` → `messages_fr` → `messages`. A
missing key throws `MissingResourceException`.

> ⚠️ **`.properties` files are ISO-8859-1 by default before Java 9** — non-ASCII needed
> `\uXXXX` escapes. **Since Java 9 they're read as UTF-8** (10.2). Another reason to be on
> a current JDK.

## `MessageFormat` and pluralisation

```java
MessageFormat.format("Hello, {0}! You have {1} messages.", name, count);
```

**Pluralisation is not "add an s"** — languages have different numbers of plural forms
(Arabic has six; Polish has three; Japanese has one).

```java
var fmt = new MessageFormat("""
    {0,choice,0#no items|1#one item|1<{0,number,integer} items}""", Locale.UK);
fmt.format(new Object[]{5});      // "5 items"
fmt.format(new Object[]{1});      // "one item"
fmt.format(new Object[]{0});      // "no items"
```

> For serious i18n, use **ICU4J's `PluralFormat`** — it implements the CLDR plural rules
> properly. The JDK's `ChoiceFormat` only handles numeric ranges, which is not the same
> thing as grammatical plural categories.

## ⭐ `Collator` — locale-correct sorting

```java
var list = new ArrayList<>(List.of("äpfel", "zebra", "apple"));

Collections.sort(list);                                   // ⚠️ sorts by UTF-16 CODE POINT
// [apple, zebra, äpfel]   ← ä sorts after z. Wrong in every language.

var collator = Collator.getInstance(Locale.GERMAN);
list.sort(collator);                                      // ✅ [äpfel, apple, zebra]
```

**Measured**, the same three words under three orderings:

| Ordering | Result |
|---|---|
| `Collections.sort` (code point) | `[apple, zebra, äpfel]` — ⚠️ `ä` after `z` |
| **German** `Collator` | `[äpfel, apple, zebra]` — `ä` sorts **with `a`**, then `pf` < `pp` |
| **Swedish** `Collator` | `[apple, zebra, äpfel]` — ⭐ `ä` is a **separate letter, after `z`** |

> ⭐ **German and Swedish disagree about the same three words**, and neither matches the
> code-point order. There is no locale-independent "alphabetical" — which is the entire
> reason `Collator` exists.

> ⭐ **`String.compareTo` compares UTF-16 code units** (5.5) — it is not alphabetical order
> in any language. Accented characters sort after `z`, uppercase sorts before lowercase
> (`"Zebra" < "apple"`).

```java
collator.setStrength(Collator.PRIMARY);     // ignore case AND accents
collator.setStrength(Collator.SECONDARY);   // accents matter, case doesn't
collator.setStrength(Collator.TERTIARY);    // everything matters (default)
```

As the table above shows, this is not hypothetical — `Collator` encodes each locale's
actual rules.

> ⚠️ **`Collator` is not thread-safe.** Create one per use, or use
> `collator.getCollationKey(s)` to precompute sortable keys (much faster for large sorts).

## Unicode normalisation

Covered in 10.2 — repeated here because it belongs to text handling:

```java
Normalizer.normalize(s, Normalizer.Form.NFC);
Normalizer.isNormalized(s, Normalizer.Form.NFC);
```

`"é"` (one code point) and `"e" + combining acute` (two) render identically and are
different strings. **Normalise to NFC at the input boundary** — usernames, search terms,
filenames, anything compared or used as a key (2.5).

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `toUpperCase()` with no locale | **Breaks in Turkish.** Use `Locale.ROOT` |
| `Collections.sort` on user-visible strings | Code-point order, not alphabetical |
| `"$" + amount` | Wrong symbol, separator and placement for most locales |
| Default locale anywhere | Machine-dependent behaviour |
| A fixed date pattern for users | Imposes your country's day/month order |
| "Add an s" pluralisation | Many languages have 3–6 plural forms |
| `Collator` as a shared field | Not thread-safe |

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `new Locale("en", "GB")` | `Locale.of(...)` `Java 19` |
| `String.toUpperCase()` for protocol comparison | `toUpperCase(Locale.ROOT)` or `equalsIgnoreCase` |
| `String.compareTo` for display sorting | `Collator` |
| Hand-built currency strings | `NumberFormat.getCurrencyInstance` |

## Recap

| Concept | One line |
|---|---|
| **Default locale** | Machine-dependent. **Never rely on it** |
| ⭐ **`Locale.ROOT`** | For machine-facing text. The **Turkish `i`** is why |
| `NumberFormat` | Separators, currency, percent — all locale-specific |
| `DateTimeFormatter` | `ofLocalizedDate` for users; explicit patterns for machines |
| `ResourceBundle` | `messages_fr.properties`, with fallback. **UTF-8 since Java 9** |
| `MessageFormat` | Pluralisation — use ICU4J for real i18n |
| ⭐ **`Collator`** | **`compareTo` is not alphabetical.** Not thread-safe |
| `Normalizer` | NFC at the boundary (10.2) |
