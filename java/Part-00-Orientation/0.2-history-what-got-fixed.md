# 0.2 — The history, as a story of what got fixed

> **What this is:** You do not need dates. You need to be able to look at a piece of
> Java code or advice and know **which era it came from** — because Java has thirty
> years of history and a lot of it is dead.

---

## Coming from JS/Python/Dart

JS has the same problem (`var` → ES6, callbacks → promises → async/await) and you
already know how to spot pre-2015 JavaScript on sight. Java's version of that break is
**Java 8 (2014)** — and unlike JS, the old style still *compiles perfectly*, so nothing
warns you that you're writing 2009 code.

---

## The eras

### 1996–2004 — the verbose era
Applets, no generics, casting everything out of collections by hand.

```java
// This is what Java looked like. It still compiles.
List names = new ArrayList();
names.add("Basha");
String n = (String) names.get(0);   // cast required, could blow up at runtime
```

### Java 5 (2004) — the type system grows up
**Generics, enums, annotations, for-each, autoboxing, `java.util.concurrent`.**

> Half of what you write daily was introduced here. The cast above disappears:
> ```java
> List<String> names = new ArrayList<>();
> String n = names.get(0);   // no cast, checked at compile time
> ```

### Java 6–7 (2006–2011) — drift
Sun collapsed, Oracle acquired them, years of near-silence.
Two things worth having: **try-with-resources** and **NIO.2** (`Path`, `Files`).

### Java 8 (2014) — **the break**
**Lambdas, streams, `Optional`, `java.time`, default methods.**

Still the most-installed version on earth, and the reason so much online Java looks the
way it does. When someone says "modern Java" and means lambdas, they mean 2014.

### Java 9 (2017) — the split
The module system arrives and is **mostly ignored** by application developers. The
six-month release cadence begins. The JRE disappears.

### Java 10–16 (2018–2021) — the quiet rebuild
`var`, text blocks, switch expressions, **records**, pattern matching.
Small, constant, compounding. This is where modern Java *syntax* starts.

### Java 17–21 (2021–2023) — the modern language appears
**Sealed classes, records and switch patterns combine into a genuinely different style.**
Virtual threads land in 21.

### Java 22–27 (2024–2026) — ergonomics and the machine
The boilerplate around `main` falls away. The Foreign Function & Memory API replaces
JNI. Startup and object headers get cheaper.

---

## The three themes running through all of it

> **Less ceremony. Stronger types. Fewer places to be wrong.**

Every change above is one of those three. If you understand that sentence, you can
predict what Java will do next.

---

## Seeing it: the same class, three eras

```java
// 2004 — the 60-line data class (abbreviated)
public class Point {
    private final int x, y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public int getX() { return x; }
    public int getY() { return y; }
    @Override public boolean equals(Object o) { /* 10 lines */ }
    @Override public int hashCode() { /* 3 lines */ }
    @Override public String toString() { /* 3 lines */ }
}
```

```java
// 2021 — a record. Identical behaviour.
public record Point(int x, int y) { }
```

That is the whole story of modern Java in two code blocks.

## ⚠️ Traps

- **Old code still compiles.** Java's backwards compatibility is extraordinary, which
  means nothing stops you writing 2009 Java in 2026. The compiler will not help you here.
- **Stack Overflow is mostly 2012.** The highest-voted answer is often the oldest one.
  Always check the date, and check whether a newer answer sits below it.
- **"Java is verbose"** is usually a statement about Java 7 that people never updated.
