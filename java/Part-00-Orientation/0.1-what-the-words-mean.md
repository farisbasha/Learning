# 0.1 — What the words mean

> **What this is:** Half of all beginner confusion in Java is vocabulary about the
> *platform*, not the *language*. Ten minutes here saves months of being confused by
> error messages and download pages.

---

## Coming from JS/Python/Dart

In Node you install **one thing** — `node` — and it is the runtime, the compiler-ish
part, and the tooling. In Python you install `python`. In Dart you install the Dart SDK.

Java splits this into named layers, and **every one of those names shows up in
error messages, install docs and job descriptions**. That's the only reason you
need to learn them.

---

## The concepts

### The four words

| Word | What it is | Analogy |
|---|---|---|
| **JVM** | The machine that runs bytecode. It is a *specification* with many implementations. | The V8 engine |
| **JRE** | JVM + standard library. Enough to **run**, not to compile. `💀 gone since Java 11` | Node without npm/tooling |
| **JDK** | JRE + compiler (`javac`) + tools. **This is what you install today.** | The full Node install |
| **Java SE** | The *specification* — the document that says what Java is | The ECMAScript spec |

And one more:

- **OpenJDK** — the reference *implementation* of Java SE, and its source code.
  Essentially all Java you will ever run is OpenJDK.

> **The takeaway:** you install a **JDK**. The JRE stopped shipping separately at
> Java 11, so if a tutorial tells you to "install the JRE", that tutorial is at
> least 8 years old — stop reading it.

### Bytecode — the whole original pitch

```
YourCode.java  --javac-->  YourCode.class  --JVM-->  runs
   (text)                    (bytecode)          (on any OS)
```

Java does **not** compile to machine code for your CPU. It compiles to **bytecode** —
a portable intermediate format that the JVM then executes. That was the entire 1996
pitch: *write once, run anywhere*.

This matters later, in two places:
- **Part 08** — the JIT turns hot bytecode into real machine code while your program runs.
- **Part 03** — generics get erased during the compile to bytecode, which explains a
  dozen rules that otherwise look arbitrary.

You can look at bytecode yourself:

```bash
javac Hello.java      # produces Hello.class
javap -c Hello.class  # disassembles it — human-readable bytecode
```

### Distributions — why there are so many downloads

These all build the **same OpenJDK source**. They differ in support terms,
licence, and who you call when it breaks:

| Distribution | Notes |
|---|---|
| **Eclipse Temurin** | Free, community, the default safe pick |
| **Amazon Corretto** | Free, AWS-supported, good on Linux/servers |
| **Oracle JDK** | Oracle's build. Licence has changed repeatedly — this is the one that made companies nervous |
| **Azul Zulu**, **Microsoft Build** | Same source, different vendors |
| **GraalVM** | OpenJDK + ahead-of-time native compilation |

**The licensing story, short version:** in 2019 Oracle changed the Oracle JDK licence so
commercial use needed payment. Everyone moved to Temurin/Corretto. In 2021 Oracle
relaxed it again (NFTC). The net result: **nobody serious worries about this anymore,
and you should just install Temurin or Corretto.**

**What to actually install:** a current LTS from Temurin or Corretto. Today that's **Java 25**.

### Running several JDKs at once

You will need this. Old projects are stuck on 8 or 17; you want to learn on 25.

```bash
# SDKMAN — the usual answer on macOS/Linux
curl -s "https://get.sdkman.io" | bash

sdk list java                  # see everything available
sdk install java 25-tem        # Temurin 25
sdk install java 17.0.13-tem   # and a 17 for old projects
sdk use java 17.0.13-tem       # switch, this shell only
sdk default java 25-tem        # switch, permanently
```

Alternatives: `jenv`, or macOS's own `/usr/libexec/java_home -V`.

## ⚠️ Traps

- **"Install the JRE"** — it hasn't existed since Java 11. Any guide saying this is stale.
- **`JAVA_HOME` vs `PATH`** — build tools (Maven, Gradle) read `JAVA_HOME`; your shell
  reads `PATH`. They can point at different JDKs, and then `java --version` disagrees
  with what your build uses. Check both.
- **Confusing JVM with Java.** Kotlin, Scala, Clojure and Groovy all compile to
  bytecode and run on the JVM. "JVM language" ≠ "Java".

## Recap

| Question | Answer |
|---|---|
| What do I install? | A **JDK** — Temurin or Corretto, current LTS |
| What runs my code? | The **JVM**, executing **bytecode** |
| What is OpenJDK? | The reference implementation everyone builds from |
| How do I switch versions? | **SDKMAN** |
