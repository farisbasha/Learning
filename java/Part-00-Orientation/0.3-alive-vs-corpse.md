# 0.3 — What is alive and what is a corpse

> **What this is:** Read this before you read anything else about Java, or you will
> waste weeks on dead ends. This is the single highest-value page in Part 00.

---

## Coming from JS/Python/Dart

You already do this instinctively in JS — you see `var self = this;` and you know
the article is from 2013. This page gives you the same instinct for Java.

---

## 💀 Genuinely gone — don't even read about these

| Thing | What it was |
|---|---|
| **Applets** | Java in the browser. Dead for a decade, API deleted in Java 26 |
| **Java Web Start** | Launching desktop apps from a web page |
| **Nashorn** | JavaScript engine inside the JVM |
| **CORBA** | Distributed object protocol from the 90s |
| **Security Manager** | Sandboxing mechanism, now disabled |
| **`Thread.stop()`** | Removed in Java 26 |
| **String templates** | Previewed in 21, **removed in 23**. You will find blog posts about them. **They do not exist.** |

---

## ⚠️ Still exist, but must never appear in new code

These compile. Your IDE will suggest them. They are all wrong now.

| Don't use | Use instead | Why |
|---|---|---|
| `Date`, `Calendar` | `java.time` — `LocalDate`, `Instant` | Mutable, confusing, timezone bugs |
| `SimpleDateFormat` | `DateTimeFormatter` | **Not thread-safe** — a classic production bug |
| `Vector`, `Hashtable` | `ArrayList`, `HashMap` | Synchronised on every call, for no benefit |
| `StringBuffer` | `StringBuilder` | Same — pointless synchronisation |
| `finalize()` | try-with-resources, `Cleaner` | Unpredictable, removed |
| Java serialization | JSON, protobuf | A long-running security disaster |

```java
// 💀 old
Date d = new Date();
SimpleDateFormat f = new SimpleDateFormat("yyyy-MM-dd");

// ✅ current
LocalDate d = LocalDate.now();
DateTimeFormatter f = DateTimeFormatter.ofPattern("yyyy-MM-dd");
```

## ⚠️ Practices that used to be taught and are now wrong

- **A getter and setter for every field.** This was never encapsulation — it's a field
  with extra steps. Expose *behaviour*, hide *state* (see 2.1).
- **Deep inheritance trees.** `Animal → Mammal → Dog → Labrador`. Composition is almost
  always the better answer (see 2.3, 2.10).
- **Checked exceptions everywhere.** The industry tried it and moved away (see Part 04).
- **Manual thread pools for I/O.** Virtual threads changed this completely (see 9.11).

---

## ✅ Things people *call* obsolete that are not

Don't over-correct. These are fine:

| Thing | Verdict |
|---|---|
| `synchronized` | Still correct, still the simplest tool. Fine. |
| **Arrays** | Fine. Sometimes the right answer for performance. |
| `null` | Unavoidable. `Optional` is for API *return* boundaries, not a `null` ban. |
| Plain `for` loops | Fine. A stream is not automatically better. |

## How to date a tutorial on sight

Open any Java article. Look for these. Each one is a red flag:

| Red flag | What it tells you |
|---|---|
| `public static void main(String[] args)` ceremony explained at length | Pre-Java 25 |
| `new ArrayList<String>()` with the type repeated on both sides | Pre-Java 7 (no diamond `<>`) |
| `System.out.println` everywhere | Pre-Java 25 (`IO.println` now) |
| XML configuration | Pre-2015 |
| `List names = new ArrayList();` raw, no generics | Pre-2004 |
| Any mention of applets | Abandon immediately |

> **Rule of thumb:** if the code uses the diamond operator `<>` and lambdas, it's at
> least 2014. If it uses `var` and records, it's at least 2021 and probably trustworthy.
