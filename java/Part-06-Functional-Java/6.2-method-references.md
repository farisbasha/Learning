# 6.2 — Method references

> **What this is:** Four forms, **one of which is genuinely confusing until someone names
> it**. This page names it.

---

## Coming from JS/Python/Dart

Python's `map(str.upper, words)` is exactly form 3 below — the unbound receiver. You've
used it without needing a name for it. JS has no equivalent (`arr.map(x => x.toUpperCase())`
is the only option).

---

## The concepts

A method reference is a lambda whose body does nothing but call one existing method.

```java
x -> x.toUpperCase()          →     String::toUpperCase
x -> IO.println(x)            →     IO::println
() -> new ArrayList<>()       →     ArrayList::new
```

---

## The four forms

### 1. `Type::staticMethod`

```java
Function<String,Integer> f = Integer::parseInt;
// equivalent to:  s -> Integer.parseInt(s)

list.stream().map(Integer::parseInt)
list.stream().map(Math::abs)
list.forEach(System.out::println)      // ← actually form 2, see below
```

The lambda's arguments become the static method's arguments, in order.

### 2. `instance::instanceMethod` — **bound**

Bound to **that specific object**, captured when the reference is created:

```java
String prefix = "Hello, ";
Function<String,String> f = prefix::concat;
// equivalent to:  s -> prefix.concat(s)

f.apply("world");        // "Hello, world"
```

```java
IO::println                    // bound to the IO class's stream
System.out::println            // bound to the System.out OBJECT
var logger = new Logger();
list.forEach(logger::log);     // bound to `logger`
```

> ⚠️ The receiver is evaluated **once**, when the method reference is created — not on
> each call. If `prefix` were a field that changed later, the reference would still hold
> the old object.

### 3. ⭐ `Type::instanceMethod` — **unbound** (the confusing one)

```java
Function<String,String> f = String::toUpperCase;
f.apply("hi");        // "HI"
```

**Here's the confusion:** `toUpperCase()` takes **zero** arguments, but `Function<String,String>`
needs **one**. Where does it go?

> **The first parameter becomes the receiver.**

```java
String::toUpperCase          ≡     s -> s.toUpperCase()
                                   ↑
                        the first argument IS the object you call it on
```

The general rule:

```java
Type::method   with arguments (a, b, c)    ≡    (a, b, c) -> a.method(b, c)
//                                                          ↑        ↑
//                                                      receiver   the rest
```

More examples:

```java
BiFunction<String,String,Boolean> f = String::startsWith;
f.apply("hello", "he");                     // true
// ≡ (s, prefix) -> s.startsWith(prefix)

Comparator<String> c = String::compareTo;
// ≡ (a, b) -> a.compareTo(b)

list.stream().map(User::name)               // ≡ u -> u.name()
list.stream().filter(String::isEmpty)       // ≡ s -> s.isEmpty()
```

**Telling form 2 and form 3 apart** — they look identical:

```java
String prefix = "Hi";
prefix::concat        // form 2 — BOUND. `prefix` is a variable holding an object
String::concat        // form 3 — UNBOUND. `String` is a type
```

Lowercase-ish thing on the left → an object → bound.
A type name on the left → unbound, first arg becomes the receiver.

### 4. `Type::new` — constructor references

```java
Supplier<ArrayList<String>> s = ArrayList::new;
// ≡ () -> new ArrayList<>()

Function<String,Integer> f = Integer::new;        // ⚠️ deprecated constructor
Function<Integer,ArrayList<String>> g = ArrayList::new;   // the (int capacity) constructor
```

Which constructor gets picked is decided by the **target functional interface's shape**:

```java
Supplier<List<String>>            → new ArrayList<>()
Function<Integer, List<String>>   → new ArrayList<>(capacity)
```

```java
// common uses
map.computeIfAbsent(key, k -> new ArrayList<>())      // can't use :: here — k is unused
stream.collect(Collectors.toCollection(TreeSet::new))
stream.collect(Collectors.toMap(User::id, Function.identity(), (a,b)->a, LinkedHashMap::new))
```

**Array constructor references:**

```java
IntFunction<String[]> f = String[]::new;
f.apply(5);                          // new String[5]

// the common use — Stream.toArray needs one
String[] array = stream.toArray(String[]::new);
```

Without it, `stream.toArray()` returns `Object[]` (because of erasure, 3.3 — the stream
can't create a `T[]` itself).

## ⭐ When a method reference is clearer — and when it isn't

**Clearer:**

```java
.map(User::name)                     // ✅ vs  .map(u -> u.name())
.filter(Objects::nonNull)            // ✅ vs  .filter(x -> x != null)
.forEach(IO::println)                // ✅
.sorted(Comparator.comparing(User::age))
.collect(toCollection(TreeSet::new))
```

The noise (`u ->`, `x ->`) disappears and the *operation* is what's left.

**Not clearer:**

```java
// ❌ what are the arguments? in what order?
.reduce(BigDecimal::add)

// ✅ explicit is better here
.reduce((a, b) -> a.add(b))
```

```java
// ❌ unbound form when the receiver isn't obvious
.map(String::compareTo)              // BiFunction? what's compared to what?

// ❌ when you need a slight variation
.map(String::trim)                   // fine
.map(s -> s.trim().toLowerCase())    // must be a lambda — two calls
```

> **The test: does the reader have to work out where the arguments went?** If yes, use a
> lambda. Method references are for the cases where the name alone says everything.

**And one that trips people:**

```java
// ❌ you might think this works
list.forEach(this::process);         // ✅ actually fine — bound form

// ❌ this doesn't
map.forEach(IO::println);            // BiConsumer needs (k,v); println takes one arg
map.forEach((k,v) -> IO.println(k + "=" + v));   // ✅
```

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `String::toUpperCase` takes no args | The **first parameter becomes the receiver** |
| `obj::method` re-evaluates `obj` each call | It's captured **once**, at creation |
| `stream.toArray()` gives `T[]` | Gives `Object[]`. Pass `String[]::new` |
| Using `::` everywhere | Sometimes a lambda is clearer |
| `map.forEach(IO::println)` | `BiConsumer` needs two args |

---

## Recap

| Form | Syntax | Equivalent lambda |
|---|---|---|
| **Static** | `Integer::parseInt` | `s -> Integer.parseInt(s)` |
| **Bound instance** | `logger::log` | `s -> logger.log(s)` |
| **Unbound instance** ⭐ | `String::toUpperCase` | `s -> s.toUpperCase()` |
| **Constructor** | `ArrayList::new` | `() -> new ArrayList<>()` |
| **Array constructor** | `String[]::new` | `n -> new String[n]` |

> **The unbound rule:** `Type::method` with args `(a, b)` means `a.method(b)` — the first
> argument is the receiver.
