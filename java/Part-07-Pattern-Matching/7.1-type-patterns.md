# 7.1 — Type patterns

> **What this is:** The smallest piece of pattern matching, and **an immediate daily
> improvement**. Five minutes to learn, used constantly. `Java 16`

---

## Coming from JS/Python/Dart

Closest thing you know: TypeScript's type narrowing.

```typescript
if (typeof x === "string") {
    x.toUpperCase();      // TS narrowed x to string automatically
}
```

Java couldn't do this until 2021 — you had to test, then cast, manually.

---

## The concepts

### The three-line cast dance it replaces

This fills older codebases:

```java
// ❌ pre-Java 16
if (o instanceof String) {
    String s = (String) o;        // ← say "String" a third time
    IO.println(s.length());
}
```

You name the type **three times**: in the test, in the cast, in the declaration. And the
cast can't fail — you just checked — but the compiler makes you write it anyway.

```java
// ✅ Java 16+
if (o instanceof String s) {
    IO.println(s.length());
}
```

**Test and bind in one step.** The variable `s` is declared by the pattern, already typed,
already cast.

### ⭐ Flow scoping — where the binding is in scope

This is the part that's cleverer than it looks. `s` is in scope **exactly where the
compiler can prove the pattern matched.**

```java
if (o instanceof String s) {
    s.length();          // ✅ in scope
}
s.length();              // ❌ out of scope
```

**Combining with `&&`** — the binding is available immediately to the right:

```java
if (o instanceof String s && s.length() > 5) {      // ✅ s usable in the same condition
    IO.println(s.toUpperCase());
}
```

```java
if (o instanceof String s || s.length() > 5) {      // ❌ s not definitely assigned
```

With `||`, the right side runs when the pattern *didn't* match — so `s` doesn't exist.
The compiler knows.

**⭐ Negation flips the scope** — this is the genuinely surprising one:

```java
if (!(o instanceof String s)) {
    return;              // s NOT in scope here
}
// but s IS in scope here — we can only reach this line if the pattern matched
IO.println(s.length());  // ✅
```

This enables the **guard-clause style** (4.4), which flattens deeply nested code:

```java
// ❌ nested
public String describe(Object o) {
    if (o instanceof User) {
        User u = (User) o;
        if (u.isActive()) {
            return u.name();
        }
    }
    return "unknown";
}

// ✅ flat
public String describe(Object o) {
    if (!(o instanceof User u)) return "unknown";
    if (!u.isActive())          return "unknown";
    return u.name();
}
```

It also works with `while` and the ternary:

```java
while (!(it.next() instanceof String s)) { ... }
String r = o instanceof String s ? s : "none";
```

### Where you'll use it most

**`equals` implementations** (2.5) — for a `final` class:

```java
@Override
public boolean equals(Object o) {
    return o instanceof Point p && x == p.x && y == p.y;
}
```

That's the whole method. Compare with the four-line version from 2.5.

**Handling heterogeneous input:**

```java
String format(Object value) {
    if (value instanceof Integer i)    return "int: " + i;
    if (value instanceof String s)     return "str: " + s.strip();
    if (value instanceof List<?> list) return "list of " + list.size();
    return String.valueOf(value);
}
```

> Note `List<?>` not `List<String>` — erasure forbids the latter in `instanceof` (3.3).

**Narrowing after a generic or `Object` boundary** — parsing, reflection, JSON trees,
visitor-ish dispatch.

### Generic and array types work too

```java
if (o instanceof Map<?, ?> m)    { m.size(); }
if (o instanceof int[] arr)      { arr.length; }
if (o instanceof String[] arr)   { ... }
```

## ⚠️ Traps

| Trap | Reality |
|---|---|
| `o instanceof List<String> l` | ❌ Illegal — erasure (3.3). Use `List<?>` |
| Expecting the binding after `\|\|` | Not definitely assigned. Compile error |
| Forgetting negation flips scope | `if (!(o instanceof X x)) return;` leaves `x` in scope after |
| `null instanceof String s` | **`false`** — always. `null` never matches a type pattern |
| Shadowing an existing variable | The pattern variable is a real declaration; the name must be free |

That `null` one matters and is deliberate:

```java
Object o = null;
if (o instanceof String s) { }     // false — no NPE, just doesn't match
```

Type patterns are **null-safe by design**. You never need a separate null check before
one. (In `switch`, null is handled differently — 7.2.)

---

## 💀 Dead / never use

| Thing | Instead |
|---|---|
| `if (o instanceof X) { X x = (X) o; ... }` | `if (o instanceof X x)` |
| A null check before `instanceof` | `instanceof` already returns false for null |

## Recap

| Concept | One line |
|---|---|
| `o instanceof String s` | **Test and bind in one step.** `Java 16` |
| Replaces | The three-line test-cast-declare dance |
| Flow scoping | In scope exactly where the compiler proves the match |
| `&&` | Binding usable immediately to the right |
| **Negation** | `if (!(o instanceof X x)) return;` → `x` in scope **after** |
| `null` | Never matches. No NPE |
| Erasure | `List<?>` yes, `List<String>` no |
